# 0001 Phase slot 排序在全员声明后才启用

- 状态:accepted
- 关联:`agent/lifecycle/phase.py`、`PluginManager._order_phase_modules`

## 背景

原有 lifecycle 按注册顺序执行插件模块,模块之间无法表达先后依赖。两个插件改同一段
上下文时,先后取决于加载顺序这种偶然因素。照 Reference `agent/lifecycle/phase.py`
引入 slot 依赖图后,需要决定对存量插件怎么生效。

## 决定

`PluginManager._collect` 只在**该相位全部模块都声明了 slot** 时启用拓扑排序;
只要有一个模块没声明,整个相位保持原有的注册/优先级顺序。

声明错误(slot 重复、循环依赖)只记 error 并回退原顺序,不让异常打挂整个相位。

## 理由

混用会让未声明 slot 的老模块被隐式重排。一个从未改过的插件因为别人加了 slot 而换了
执行位置,这种偶然的顺序变化比"顺序不可控"更难排查——后者至少是稳定可复现的。

## 替代方案

- 立即全局启用,未声明 slot 的模块按注册顺序补一个隐式 slot:被否决,等于强行重排存量。
- 用配置开关控制:被否决,增加一个需要长期维护的旋钮,而迁移完成后它就没用了。

## 影响

插件全部迁移到 slot 后自动获得依赖排序,无需再改 runtime。迁移期间行为与之前完全一致。

## 验收

- 全员声明 slot 时按 requires 拓扑排序,依赖缺失的模块及其下游被级联禁用;
- 混用时顺序与引入本机制之前一致;
- 成环时保持原顺序并记录 error,相位仍可执行。
