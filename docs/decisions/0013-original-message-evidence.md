# 0013：原文证据、固定读取视图与独立重建输入

日期：2026-10-19。状态：已实现。

## 决定

事件记忆的事实边界位于原始消息。学习图可以发现联系，但输出中的人物、对象、关系和更正
必须能够回到稳定原文；展示副本和模型提取都不获得改写历史的权限。

原 Akasha2 返回 JSON 消息 ID 列表，fetch 工具只直接解析单个 ID，导致模型需要自行拆解范围。
`SessionManager.fetch_messages` 现在直接接受召回的完整 `source_ref`，定位全部 anchor 后合并
邻近窗口，返回稳定身份、会话、顺序、日期和 anchor 标记。部分来源缺失时拒绝部分成功。
单 ID 和真实存在的旧 `session:seq` 位置继续可用。

原恢复逐条打开源库，一次召回也为每个命中独立读原文。现由 `session.turn_source` 提供只读
SQLite 快照；Akasha2 一次恢复或一次查询在同一视图内验证全部 binding 与原文。
减少连接开销的同时，消除一次结果混入多个读取版本的窗口。读到完整旧视图是允许的；
下一次读取会发现已修改来源并失败，不能把快照等同于阻止用户编辑。

## 所有权与兼容

在线学习得到的原始向量另存入 Session 的现有 `message_embeddings` 表，按原文 ID、内容 hash
和完整空间身份定位；空间包含模型、端点和声明维度。缓存先于图学习落盘，学习中断后复用已经
成功保存的向量。新输入先固定为 float32，再参与在线学习与重放；checkpoint 中已经归一化的
向量按原值恢复，避免再次归一化造成末位漂移。

重建只接收 Session 源库和固定向量，临时工作区没有原图，不调用 provider。新缓存严格匹配
完整空间；已有 model-only 缓存继续兼容，但输出明确标记 `legacy_model_only`，不证明其端点身份。
旧历史不会自动回填缓存；缺少合法输入向量时仍严格失败。缓存与图是前后两个提交，不是跨库事务。

原文 owner 仍是 Session。图学习、扩散、遗忘、数据库 schema 与固定算法文件不改，已有
checkpoint 直接恢复。显式 query/fetch 不学习，不提供 graph feedback 或跨租户授权。
未来的查询 receipt 与 scope 路由由各自 owner 设计，不通过新增一份可编辑消息副本实现。

## 验证

真实 SQLite 回归覆盖范围回源、跨会话窗口去重、缺失来源、旧位置不存在时拒绝返回邻居，
以及读取期间有外部 writer 更新时的单视图一致性。新增学习失败免重算、不同端点缓存隔离、
丢图断网重建与维度可省略的回归。全量 702 项测试与 4 个 subtests 通过。

固定旧版本在三张原图上执行相同恢复与查询，原文和学习状态保持不变，返回证据与顺序一致。
修复二次归一化后分数最大差为 `1.11e-16`；最终版本自身重启前后记录严格相等。
源库连接次数由每个历史 turn 三次变为恢复总共两次，命中原文查询共用一次连接。
完整计时、源码身份、Step5 工具闭环和专项任务见[本轮实验报告](../operations/evaluations/2026-10-19-episodic.md)。
