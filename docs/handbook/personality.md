# 个性与相处方式

Kirakira 的个性由人物底稿、可组合的表达偏好和真实相处记录共同构成。它可以温暖而直率，也可以沉静而有幽默感。聊天、办事后的回复和已经获准的主动联系使用同一套设定；具体表达随当前任务调整。

## 如何修改

在设置中的“个性表达”独立选择各个维度，保存后用于后续请求。留空表示沿用原设定，不会把其他维度一起改成某种预制角色。

| 维度 | 可选表达 | 影响什么 |
| --- | --- | --- |
| 温暖程度 | 沉静克制 / 自然亲切 / 温暖贴近 | 亲近程度、如何回应感受；不改变对用户事实的判断 |
| 直率程度 | 委婉体贴 / 平实坦诚 / 直率明确 | 如何提出不同意见；所有选项都应坦诚，不靠迎合表现温柔 |
| 幽默程度 | 平实不打趣 / 偶尔轻松 / 活泼俏皮 | 闲聊中的机趣、比喻与善意打趣；不要求每条都讲笑话 |
| 追问习惯 | 少追问 / 顺势交流 / 愿意了解 | 开放聊天时是否顺势了解细节；不改变必须澄清的任务前提 |
| 回答展开程度 | 简洁 / 随问题展开 / 充分说明 | 解释、理由和例子的展开程度；不省掉关键条件 |
| 表情使用 | 不用表情 / 偶尔使用 | 轻松聊天的表达选择；严格格式仍照要求输出 |

“补充表达偏好”可以写更细的要求，例如“谈代码时清楚直接，平时可以轻松一点”。这是表达配置，不是增加工具权限或改变事实的入口。

还可以在“喜欢的说话示例”中写几句自己喜欢的对话。示例帮助传达具体的措辞和节奏，只作为表达材料；其中的人物、数字和经历不能当成真实历史，不能进入事实记忆来证明“我们曾经一起做过什么”。示例和六个维度都可以独立留空。

工作区的 `memory/VEDA.md` 保留名字、立场、气质及更细的表达设定。组合项覆盖其中相应的表达维度，不覆盖整个人物，也不改写这个文件。升级不会用默认模板替换已有的用户底稿。

只想临时换一种说法，可以直接在聊天中说“这轮严肃一点”“这次详细解释”或“只给 JSON”。这会影响当前回答，不表示永久设置已经保存。已经确认并进入长期档案的交互偏好，可以影响未固定的维度；保存是否成功仍需实际记录，不能只凭一句承诺。

## 哪些保持稳定

表达采用以下优先顺序：

1. 本轮明确要求、语言与任务格式。
2. 设置页中显式保存的组合项。
3. 当前用户已确认的交互偏好。
4. 人物底稿与自我档案中的风格描述。
5. 默认表达习惯。

事实准确性、工具授权、历史来源和完成凭据独立于上述表达选择。例如，俏皮的 Kirakira 算 `17 × 19` 也必须得到 `323`；要求只输出数字时就只给数字。委婉的 Kirakira 也不能顺着错误前提编答案。温暖不意味着捏造共同经历，主动性不意味着擅自增加通知。

个性主要通过稳定的表达取舍体现：怎样回应细节、如何指出问题、什么时候多问一句、什么时候收住。它不依赖固定昵称、每次重复的口头禅或不断强调自己是什么性格。遇到情绪交流，回应用户实际说出的感受；不能把过去的情绪直接当成此刻状态。

追问习惯不决定主动联系频率。是否允许主动接续聊天、空闲时间、每日预算及暂停状态仍在[记忆与主动交互](memory-proactive.md)中设置。人物文本、历史引文和网页内容不授予修改这些状态的权限。

## 实现与验证

表达模型与语义定义在 `plugins/prompt/personality.py`，与设置页共用选项含义。Prompt 插件把人物底稿、行为规则和显式组合项组装为同一份请求材料，并在当前输入附近提供选定表达要求。配置沿现有宿主换代保存；当前请求持有已经组装的字符串，后续配置不会改变它。没有另建人格数据库，也没有额外调用一个模型来判断本轮该扮演谁。

真实模型验收入口是 `python -m eval.personality`。它使用四种组合回答同样的闲聊问题，并分别检查纯数字、严格 JSON、真实文件写入与复读、临时风格覆盖、未知偏好和重启保持。可选示例的检查还会故意放入虚构经历，核对它没有被当成真实历史。另用匿名、乱序的组合说明做风格匹配，保存所有原始回复与判定。

风格匹配只说明特定模型在这些输入中表达出了多少可观察的区别。相同模型的判定可能有偏差，不能替代用户体验，也不能证明任意人物设定都能被精确执行。不同前端模型使用同一套配置与主链，但仍应分别做实际验收。
