# 证据与验证

这一页先说本项目**最值得称道的四件事**，每件都给出具体数字和可复核的记录；随后是全部报告的索引。每项结论的分母和条件写在对应报告里，复现命令见[评测入口](../../eval/README.md)。

## 一、召回能查到底，而且查得到出处

记忆不止"想起来"。每次召回留下**不可变、可重放的回执**：被呈现的消息身份、原文字符范围、来源会话与时间都固定下来；之后可以沿同一回执读回**精确的原文窗口**，而且**只能读这次确实呈现过的消息**——准入由回执决定，不能凭空填一个消息 ID。每次读取在 Ledger 留下绑定真实调用的 `SourceProof`。

真实模型实测：在一份 **10,894 字符**的原文里，模型用 `search_memory_source` 定位到第 8400–9200 字符窗口，答出"预算由 500 更正为 760、必须防水、只在周末"，`tool_source_proofs: 3`、`search_windows: 2`，且 `query_contains_reference_answers: false`、`exact_offset_supplied: false`——没有给任何提示。

固定语料的取证实验里，同一 6000 字符上限下加入按需读取后，参考值原文覆盖由 **4/12 升到 9/12**，末页事实由 **0/4 升到 4/4**，平均保留材料反而**减少 43.78%**。

## 二、过去的条件参与今天的决定，而且能被纠正

主动交互不是定时打扰。新事件只提供新事实，**预算、时间、使用限制来自过去的对话**，两者合起来决定分享还是跳过，结果能追溯到实际读过的用户记录。

六组受控邮件（邮件完全相同，只改另一个会话里的个人条件）：12 次调查**全部 12/12 呈现了对应历史**，**11/12 选择了预期的分享或跳过**。误判的那一次完整保留：模型找到了原话却误读主语，跳过了本可考虑的方案；用户澄清后以新规则复查同一封邮件，得到确认投递，旧误判和原文都在。

这正是"可纠正"的证据——不是不会错，是错了能查清、能改、能复查。

## 三、知道自己花了多少，并且把它降下来

多数项目说不出自己的记忆每轮花多少上下文。本项目有可复现的开销测量，并据此做了优化：

| | 改前 | 改后 |
| --- | ---: | ---: |
| 每轮实时召回注入 | 2393 字 | **757 字**（−68.3%） |
| 学习 150 轮 | 47.66 s | **20.34 s** |
| 单次检索均值 | 47.96 ms | **11.62 ms** |
| 长会话召回整体耗时 | 14.78 s | **8.91 s** |

机制是：原文仍在当前对话里的候选不再重复注入正文，改为一行索引并保留可读回出处的 `ref`；两个判断在首次查询时冻结进回执，重渲染与重启字节一致。开销类各跑三次取中位数（`eval.recall_cost`、`eval.memory_cost`）。

## 四、来源与边界是可核对的，不是声明

这是一个基于上游 [akashic-agent](https://github.com/kachofugetsu09/akashic-agent) 的发行版，来源纪律做到逐文件：**969 个文件按哈希固定**，12 个补丁工件**逐个应用到基线后与本仓库逐字节一致**（比只比对摘要更强）。采纳了什么、拒绝了什么及理由、以及刻意与上游不同的三处，都记录在 `third_party/UPSTREAM.json` 的 `reviewed_updates` 里——拒绝是写下来的决定，不是无人过问的空缺。
[第三方来源声明](../../third_party/THIRD_PARTY.md)

工程不变量由 **479 项回归**守住，而且测的是不变量而非冒烟：scope 路由不得阻塞事件循环、v3 之前的检查点必须被拒绝而不是静默重写、索引行必须可引用可读取、关注权重必须有上下界且单调。

## 读这些数字时请注意

报告中的数字属于各自的实验版本。功能回归、公开回答质量、实际投递和真实用户效果**各有自己的分母，不合并成一个"成功率"**；失败、开销与版本条件都保留在报告里，便于核对而不是便于好看。

尚未验证的部分同样写明：跨模型一致性、长期陪伴的实际价值、主动联系的有用与误打扰比例，都需要连续真实使用才能回答。[交付路线](../status/roadmap.md)记录仍待补齐的工作。

旧本机工作区的一次性切换报告与原始日志已退出当前文档，历史仍在 Git；现行迁移方法见[启动和迁移](../handbook/start.md#既有-kirakira-数据)。
