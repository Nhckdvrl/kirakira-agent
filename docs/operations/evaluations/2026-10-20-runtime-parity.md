# 重构后的功能与性能复核

结论：已接入的主链通过功能验证；完整主链的本地吞吐发生明确回退，不能宣称性能完全保持。
本轮只修复验证脚本和记录结果，没有修改生产运行逻辑或开展性能优化。

## 测试数量

实际 collection 为 **77 个文件、662 个未展开参数的测试节点，加 43 个参数化扩展，共 705 项**。
上一轮从 738 清理到 705，属于保守清理；不能把剩余数量主要解释成参数化，也不能拿数量当质量证明。

按文件名归类，记忆/召回 155 项、界面/渠道/投递 79 项、主动/调度 118 项，其余主链、扩展、工具等 353 项。
这些是全项目测试，不能说成 705 个核心功能。测试未被打包进运行模块，也不构成生产运行开销。

## 功能证据

生产版本固定为 `bdf0aaf849e1b1c2081414d6b501d3ec52cab228`：全量 705 项及 4 项子测试通过，
真实 Step Token Plan 最终代码 8/8 场景通过；接入期间三批合计 38/38，范围见
[原生组合验证](2026-10-20-native-composition.md)。

本轮最终压力对照每版本两次，每次 1,000 轮、64 个 Session、5,000 次工具调用。
四次均为 1,000/1,000 completed；每个 ticket 的 counter 效果只发生一次，77 次当前生成重试不重复效果；
未结算执行为零，每会话同时执行峰值为一，独立读取峰值为四；重启后均保留 2,000 条原始消息。

每对实验的全部 1,000 个 ticket、2,077 次规范化模型请求摘要逐项相等。
这是确定性模型协议 fixture 的功能证据，不是外部模型的真实任务成功率，也不表示上游全部功能齐全。

## 性能对照

基线为重构前 `980fcbd726c9587168b8ad0b6b4598cf6ae6d9e2`，当前为 `bdf0aaf` 的生产代码。
同机、同一 Python 3.14.6 `.venv`、同一验证脚本；模型由确定性 fixture 替代，网络调用为零。
压力实验按旧→新、新→旧两个顺序执行；micro 每版本两次，每次预热 2 次、测量 30 次。

| 负载 | 重构前 | 重构后 |
| --- | ---: | ---: |
| 千轮吞吐（两次的中位数） | 87.19 轮/s | 54.15 轮/s |
| admitted→完成 p95（两次的中位数） | 1,007.68 ms | 1,479.30 ms |
| 四片段短流 p50（60 样本） | 1.272 ms | 1.382 ms |
| 2,000 片段流 p50 | 45.145 ms | 45.855 ms |
| 100 步日志未结算检查 p50 | 0.397 ms | 0.393 ms |
| 八个独立 25ms 读取 p50 | 57.677 ms | 57.373 ms |

吞吐下降 **37.90%**。两轮原始吞吐分别为旧版 86.48 / 87.90，新版 53.96 / 54.34 轮/s。
局部 I/O、日志和工具并发路径基本保持；完整主链增加了持久输入和回复程序的工作。
高并发本地吞吐不能换算成真实聊天端到端延迟；这里未测量网络模型延迟。
两次重复用于确认明显回退，不支持跨机器或细微差异的统计结论。

## 额外工作的证据

另用 10 轮、2 个 Session 做 SQL trace，包含构造和重启，不使用这次 trace 的耗时作性能结论。
Session 数据库 COMMIT 由 **41 增至 321**；执行日志数据库均为 161。
新增 `ledger_inputs` 和 `reply_programs` 的持久记录与更新会产生额外耐久写入。
这些计数证实新增工作，尚未把所有时间增量分别归因到序列化、查询、提交或原生 Fiber。

旧版会在已清空工具后残留插件工具目录材料。最终对照显式停用订阅扩展的旧/新两种身份，
使模型请求逐项相同；此前预检和未统一工具目录的结果仅保留为辅助记录，不用于最终请求等价结论。
一次预检因旧版 MCP 子进程没有使用项目 Python 的 PATH 而启动失败，随后统一了同一环境。

## 结果与复现

[记录文件](../artifacts/runtime-parity/2026-10-20.json)保存 micro 逐样本、压力聚合、源码哈希、
请求等价摘要及 SQL 计数。完整逐 ticket JSON 保留在本次隔离运行目录，路径和摘要见记录文件。
压测脚本补齐新旧目录适配和正确的来源哈希；不再在千轮执行结束后因旧路径丢失而写报告失败。

```bash
uv run --frozen pytest --collect-only -q
uv run --frozen python eval/benchmarks/core.py \
  --implementation /path/to/checkout --repeats 30 --output /tmp/micro-new.json
uv run --frozen python eval/benchmarks/runtime.py \
  --implementation /path/to/checkout --without-extensions \
  --workspace /tmp/pressure-new --output /tmp/pressure-new.json \
  --turns 1000 --sessions 64
```

每次使用新的 workspace 和输出。旧 checkout 不另建 Python 环境；两个实现都使用项目的同一解释器。
新增耐久状态属于升级后功能的一部分，以上结果覆盖整条主链的成本。
