# 个人伙伴链路与可组合个性实测

日期：2026-10-22。定位仍是陪伴型、助理型、主动交互型的个人 Agent。本轮把日常话题接续、长原文定位和个性组合接入既有 Runtime，分别检查表达、事实、执行与交付。

完整输入、回复、配置、出处、实现摘要及开发失败见[证据文件](artifacts/2026-10-22-companion-personality/evidence.json)。每轮实验有自己的实现摘要，不把不同版本的结果拼成一次试验。

## 设计落地

个性由 `VEDA.md` 人物底稿、六个独立表达维度、补充偏好和可选说话示例共同构成。未设置的维度继承原设定；结构化选项覆盖对应风格，补充文字和示例只细化剩余空间。本轮明确要求与格式优先。事实、工具授权和完成凭据仍有固定要求，示例不能变成真实经历。使用方式见[个性与相处方式](../../handbook/personality.md)。

配置沿已有宿主持久保存、换代生效，不改写用户的人物文件。表达编译不增加模型调用，不用另一个模型在每轮决定“扮演谁”。对话与 Wake 读取相同的 Prompt 配置，已经组装的请求保持不变。

空闲提案区分 conversation、assist、research，聊天接续有独立开关，不必伪装成研究成果。三者继续共用历史核对、预算、分享或跳过、投递与恢复。原文导航通过 `search_memory_source` 在此前召回已准入的来源中查找真实窗口，保留原始位置与工具出处，不新建事实库。

| 记忆主链 | 13/13 | 渠道学习、SDK/RPC、原文读取与检索、历史参与提醒、显式反馈与重启 |

| 四种个性组合的基础功能 | 33/33 | 同题闲聊、纯数字、严格 JSON、真实文件写入与复读、临时要求、未知偏好及重启；不是人格准确率 |

这些分母含义不同，不相加为一个“Agent 成功率”。原生源码检查覆盖 977 个固定参考文件，这是结构与来源检查，不能替代功能验收。额外两项记忆用例没有合并进 13 项主链，以免重复计数。

## 个性具体改变了什么

单维度实验固定其余五项，只改变待测项。所有请求经过正式对话接纳、模型与工具链；传输观察确认当前显式组合确实出现在实际模型请求中。

| 只改变的项目 | 同一个输入 | 实际观察 |
| --- | --- | --- |
| 展开程度：简洁 → 充分说明 | 解释平均数与中位数，计算 2、3、10 | 回答 85 → 389 字符；两次均得平均数 5、中位数 3，要求的结果行保持正确 |
| 追问习惯：少追问 → 愿意了解 | 收拾好了阳台，心情不错，只想聊聊 | 前者 23 字符、0 个问题；后者 43 字符，询问空出来的地方打算怎么用 |
| 幽默：平实 → 俏皮 | 饼干歪得像小企鹅，自己觉得有趣 | 前者回应做饼干的开心；后者继续用企鹅和模具的比喻。原文保留，没有编造“幽默分数” |

这支持“具体表达习惯可以组合调整，改变展开不必改变任务事实”。每项只有一组受控样本，不能推导所有输入下的稳定效果，也不能证明任意人物都能被精确复刻。

独立反例在说话示例里放入虚构的“共同去过月球”。实际历史题要求无真实记录时给出 `NO_SHARED_HISTORY`，最终确实返回该结果。随后计算 `17 × 19 = 323`，实际写入并复读文件；重启后配置保留，原人物文件没有改写。

## 风格辨识与现有限制

匿名评审不见预期组合标签，候选选项逐次乱序，同一回答判两次。Agent 回答预算为配置中的 4096，后续独立评审预算为 8192；原回答没有重新生成。

| 描述性检查 | 整体组合匹配 | 有效判定 | 样本 |
| --- | --- | --- | --- |
| 冻结开发题回答重评 | 11/16 | 16/16 | 四种组合，每种两条回答，各判定两次 |
| 哼唱与整理照片的新话题 | 6/16 | 14/16 | 两次没有提交合格结果，仍留在分母 |

两组样本、Prompt 和评审条件不同，不作为前后提升或退步的因果对照。模型仍会混淆相近的温暖、克制与直率风格，不能宣布“人格百分之百准确”。新话题中，少追问组合的四条回复均未向用户提问；对其七次有效问题摘录也没有找出隐含追问，原文可直接复核。

开发时有回复肯定未见画作的颜色、线条，也有回复不用问号却用“要不要”提问。模型自评曾漏掉前者，标点计数也漏掉后者。后续增强素材依据约束、显式选择问句规则并增加新话题检查；自动评审仍是辅助，不把“自评零错误”当成无编造的证明。

早期评审还出现推理占满 4096 输出预算、未提交结构化结果的情况。保留失败后，使用单独预算评价冻结文本，没有重新生成回答挑结果。真实用户是否喜欢、长期个性是否稳定，以及其他前端模型上的符合程度，仍需分别验证。

## 记忆与主动链路的具体亮点

长历史包含 10894 字符，大量过程清单中间才出现最终决定：预算由 500 改为 760，要求防水且只在周末使用。测试没有提供答案或正确偏移。SDK 与实际 Agent 都从已准入来源检索到原文，工具账本留下真实窗口出处。

同源机制实验使用相同查询、同一份原文和 2400 字符的 JSON 上限。抑制同一消息内完全重复的段落选择后，关键决定不再被重复清单挤出窗口。它不删除原文、不合并不同日期的消息，也保留仅有细微数字变化的内容。

| 窗口选择 | JSON 字符 | 窗口数 | 保留真实的 760 |
| --- | --- | --- | --- |
| 未抑制重复段落的冻结实现 | 2376 | 2 | 否 |
| 当前实现 | 2380 | 2 | 是 |

这是受控反例，不是公开回答质量榜单。局部原文导航不新增 embedding、LLM 调用或图写入；Agent 决定继续查找仍消耗正常模型轮次，整个工作流的调用与用量保留在报告中。

后续采购事件只给出 720 元防水款报价，不带历史预算与周末条件。Agent 核对现行原文后沿 Alert 确认投递，重复事件复用原身份。针对“召回 → 检索 → 继续读 → 最终分享”，Alert 上限由三轮改为六轮，保持工具范围及最终决定要求。此前三轮耗尽的失败保留。

四个兴趣话题都有用户明确邀请，实际等待五分钟后接续，结束后均保持安静。它们验证陪伴型主动交流的执行与停止，没有真人满意度或日常误打扰率。部分开发文案仍含猜测，不能当作“记忆准确理解用户”的证据。

既有[长原文问答实验](2026-10-22-memory-scenarios.md)仍单独保留：相同初始片段下，困难题中带原文支持的最终回答由 0/8 到 5/8，同时报告控制题、读取开销与失败。本轮新增正式工具、SDK 与后续行动验收，没有把旧质量分数当作新实现的重新跑分。

## 回应行为与产品辨识度的后续实验

后续核对 14 个开源项目怎样把定位落实到人物、记忆、行为、操作入口和证据中，固定 15 个仓库及 52 份文件。具体采用的取舍见[人格与言行一致](../../architecture/personality.md)，版本见[参考清单](artifacts/2026-10-22-companion-personality/design-references.json)。这是设计调研，不是对外部项目的运行成绩。

在六个表达维度之外，正式增加两种行为偏好：遇到困扰时先听或回应后给办法，普通闲聊问到再建议或合适时提一个想法。两项分别组合，当前明确请求优先，保存沿既有配置换代；不新增人格模型调用、亲密度状态或工具权限。

完整阶段与逐条复读备注见[行为证据](artifacts/2026-10-22-companion-personality/behavior-evidence.json)。开发时试过“一起理清”的中间选项，但常退化为普通安慰，也曾给用户添加未经提供的身体解释，未保留为正式选项。旧回复和评分保留。

### 固定表达，观察实际行为

最终两组各固定温暖、平实、无幽默、少追问、简洁、无表情，只改变一个行为字段。开发话题是吉他、烘焙、阳台与橱窗；最后一组为此前未用于本轮迭代的陶杯、桌游、小巷与漫画，之后没有再据其回答调整规则。每组八条独立闲聊回复，另有同一会话的两条临时要求与任务切换。

| 功能验收 | 开发组 | 新话题组 |
| --- | --- | --- |
| 八条闲聊经真实主链返回，未执行工具 | 8/8 | 8/8 |
| 两条本轮要求经同一会话返回，未安排任务 | 2/2 | 2/2 |
| 同一会话继续计算与真实文件写入、复读；持久偏好及底稿未改 | 1/1 | 1/1 |
| 重启后组合保留 | 1/1 | 1/1 |
| 本轮另跑普通 Agent 主链 | 13/13 | 同一次主链运行，不重复计数 |
| 工程回归 | 129/129 | 同一次回归，不重复计数 |

12/12 是每组功能检查，不是人格准确率。闲聊功能断言检查非空回答、实际请求采用配置、没有执行工具；是否表现出预期行为另看下面的原文和观察结果。

评审只见用户消息与回复，不见目标配置；每条判两次，共每组 20 次判定。它与回答使用同一个模型，不是独立真人评价。观察需要逐字摘录建议、问题和无依据个人断言；倾听模式夹带“先歇会儿”等建议时也不算符合。

| 同模型观察 | 开发组符合/判定 | 新话题组符合/判定 |
| --- | ---: | ---: |
| 先听，未夹带建议 | 2/4 | 2/4 |
| 回应后提供办法 | 3/4 | 3/4 |
| 普通闲聊问到再建议 | 4/4 | 4/4 |
| 合适时顺带提想法 | 2/4 | 4/4 |
| 本轮要求覆盖默认行为 | 4/4 | 4/4 |
| 合计 | 15/20 | 17/20 |
| 合格结构化判定 | 20/20 | 20/20 |

每行的四次通常来自两条回复各判两次，不能当成四位用户或四个独立场景。旧四组合的 11/16、6/16 是不同实验，不与本表合并。

值得继续打磨的区别有具体原文支持。面对同一条“收拾书架翻出小时候漫画”的消息，“问到再建议”接续回忆；“合适时提想法”提出“可以留一本在手边，之后有心情的时候随手翻两页”。另一对小巷输入也从接话变成可选的再次探访想法。两个新话题各两种设定，四条回复在八次观察中均呈现相应的建议有无。它证明这个小样本里可以改变互动习惯，未证明建议一定贴切或全部细节有依据。

### 逐条复读发现的限制

- 先听模式仍在烘焙和桌游题里夹带“今天先这样放着”“随自己心意过吧”等建议，保留为不符合。
- 开发回复曾把“今天排练”补成“排练一整天”；新话题将“偶然路过”写成“拐错一个弯”，以及从封面识别推测当年的投入和触感。后者不是用户提供的实际经历，不能作为记忆正确或理解准确的证据。
- 自动观察漏过了部分补写，也曾把明确的“可以随手拍下来”漏摘为没有建议，或在有建议时选成 reflection。既保留评分，也保留原文与复读备注，不把零报错当成无编造。
- 给办法时仍可能安排多个小动作、增加未经要求的日期，或只给泛泛的建议；“实际提出办法”与“一个好办法”分别评价。

这些复读由本次维护助手完成，未经过独立真人评分。当前证据支持可组合相处方式与正常任务的共存，尚不足以声称人格精确、长期自然或用户满意。

初始脚本还误等相同配置产生新版本，导致两个 60 秒等待超时；另发现配置保存采用补丁语义，实验需明确清空未选字段，才能保持条件独立。修正后重新运行，原始中断记录保留。早期观察把“不适用”填成空串而未通过可空枚举；改用明确的 `not_applicable` 后，对旧回复另行重评，没有重新生成 Agent 回答。开发旧回复重评为 21/24、23/24 合格判定；迁移旧回复为 19/24、24/24 合格判定。协议与观察条件改变，这些数字不表示 Agent 自身提升。

长原文导航也重新完成离线复核：相同 2400 字符上限下，冻结基线 2376 字符未保留关键值，当前 2380 字符保留；调用模型 0 次。它核对原有机制，不重算先前长原文问答的 0/8 → 5/8。

复现行为实验：

```sh
python -m eval.personality --behavior-only --chat-suite validation \
  --model-config /private/path/model.json --key-file /private/path/model.key \
  --workspace /local-disk/eval/behavior-new --output /local-disk/eval/behavior.json
```

`--judge-behavior-existing <原结果.json>` 只观察冻结回复。实际模型、预算、调用用量、每轮代码摘要及最终编译器与评测源码随行为证据保存；并发实验的墙钟时间包含共享调用槽等待，不作产品延迟结论。

后续发行检查逐字核对 wheel 中 1502 个能对应到当前仓库的文件，另核对新配置、前端资产、评测入口及源码包的准确根清单。常驻服务更新后重新发布 ready，认证后的设置接口返回 200，六个表达维度与两个行为维度可用；已有用户人物、档案和记忆文件逐字保留，空闲自动联系仍保持关闭。上线没有替用户选择新的相处偏好。

## 复核与复现

离线重算当前窗口、核对冻结基线摘要及所有窗口的原始位置，不调用模型：

```sh
python -m eval.memory_runtime \
  --verify-source-search docs/operations/evaluations/artifacts/2026-10-22-companion-personality/evidence.json \
  --output /local-disk/eval/navigation-proof-new.json
```

验证器不执行证据中的基线源码；基线核对摘要与当时输出，当前实现重新计算。

真实模型使用[通用配置](../../../eval/README.md)。`--controls-only` 单测维度控制，`--examples-only` 单测示例边界，`--style-only --chat-suite transfer` 检查新话题。重评[冻结回复](artifacts/2026-10-22-companion-personality/personality-samples.json)使用 `--judge-existing`，不重新生成答案。

最初的证据文件保留 32 个带报告的阶段，包含开发失败、DNS 中断、跨代查询类型、重复窗口、工具引用转义、执行预算与评审协议问题；另记录未开始模型测试的脚本及 Unix socket 路径初始化失败。后续行为实验单独保存。真实用户消息、账号凭据与运行日志未进入公开证据。

发行检查逐字核对 wheel 中 1141 个当前文件，新模块、前端资产及源码包来源记录均存在。常驻服务已更新，认证后的个性设置接口返回 200，Telegram 账号与轮询接入配置核对通过。原人物和记忆文件的修改时间均早于升级；已有个性及空闲配置保持默认，未自动开启主动联系。
