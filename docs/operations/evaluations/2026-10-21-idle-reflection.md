# 空闲思考：从未完成话题到有依据的主动行动

日期：2026-10-21。目标是把“有长期记忆、会主动交流并持续帮主人做事的个人 AI 伙伴”落实到一条日常学习流程。这里验证没有新外部事件时，Agent 能否从未完成话题提出有依据的研究，并在目标完成或结果重复时保持安静。

## 用户场景

先在一段历史会话中确认：概率论学习资料预算不超过 100 元，只能周末参加，线上可以，工作日到场的课程不考虑。另一段当前对话只说资料还没有选，留下候选网页，然后结束交流；当前输入不重复预算和时间条件，也没有创建定时任务或提交外部事件。

在用户已开启空闲思考并选定参考对话的前提下，运行时恢复历史，提出待研究问题。后续原生 Drift/Wake 再次核对记忆，实际读取本地受控网页：甲 80 元、周三到场；乙 90 元、周六线上。通知需要据此前条件选择乙，并有真实投递确认。之后主人明确表示目标已经完成、不再研究，新的规划应选择跳过。

早期显式交办版本已通过 8 项受控验收；跨会话版本把条件放入另一个历史会话，使用默认的通用思考范围，10 项受控验收通过。原始记录区分这些不同实验，不把它们合并成公开任务成功率。

## 代码如何支持这种体验

`plugins/drift/producer.py` 只负责有界规划和提案交接。它使用当前所选聊天模型、同一记忆程序查询服务和原始会话；没有单独的模型供应商路径。模型必须给出完整结构结果，所有引用必须来自实际呈现的历史。新研究问题至少需要一条用户原话作为目标依据；助手回复可说明进展，不能单独创建主人目标。

规划次数、来源引用和交接凭据保存在本插件的原生 OwnerState；模型调用仍由 Models 记账。提案进入已有 Drift 领域表，Wake 按原身份领取，经 Sources、Task、ReplyProgram、工具和 Delivery 执行与投递。生产端不创建第二套执行队列，也不自行发送消息。

Drift 研究继承提案的参考对话范围，收件会话可以独立。研究阶段取得配置允许的记忆、原文和网页工具；绑定历史的提案需要本次成功的记忆工具读取，才能提交分享或跳过。原提案是待核对问题，不升级为主人新指令，也不能扩大工具权限。

## 运行约束

| 控制 | 实际行为 |
| --- | --- |
| 默认关闭 | 主人选择参考对话、思考范围并开启自动思考 |
| 空闲与间隔 | 默认对话结束后空闲 5 分钟，两次规划至少相隔 1 小时 |
| 每日预算 | 默认每 UTC 日最多规划 2 次，跳过、失败和中断也计入；研究调用另计 |
| 相同讨论 | 参考对话最新用户输入及思考范围不变时，复用已有记录 |
| 有待结算提案 | 先等待现有提案结算，不继续积累候选 |
| 新输入到来 | 提交规划时原生事务检查对话变化，已观察到变化则把草稿记为过期；研究阶段再核对最新目标 |
| 暂停 | 停止新自动规划，撤回未领取的自动提案；已接受的工作保留原执行语义 |
| 交接中断 | 已持久化的提案按同一身份重放，不重新规划 |
| 回执丢失后暂停 | 撤回可能已经写入的未领取提案；已经接受的任务保留原执行状态 |
| 规划尚未完成即中断 | 标记中断、保留调用账，不自动再次调用模型 |

当前按每次新讨论进行一次有界规划；长期目标的多日重新探索与按主题的语义冷却仍需进一步设计。相同输入的确定性去重不等于所有相似话题都能被自动识别为重复。

## 验证内容与结果口径

入口 `eval.idle_reflection --implicit-goal --fault-cases` 直接使用正式插件图、隔离的项目范围、模型调用账、真实记忆读取、受控 HTTP 网页和本地 Delivery。评测将空闲与间隔配置为较短值以完成验收，生产默认值见上表。

最终记录包括模型与记忆配置、跨会话目标与条件、自动提案、原生研究和实际通知、相同讨论去重、每日预算与目标完成后跳过、暂停、交接回执丢失、重启及恢复结算。逐项结果和模型用量随[原始证据](artifacts/2026-10-21-idle-reflection/evidence.json)保存。

| 验证 | 结果 | 说明 |
| --- | --- | --- |
| 显式交办的早期学习场景 | 8 / 8 | 与跨会话版本独立保存 |
| 最终跨会话空闲思考 | 10 / 10 | 默认通用思考范围，无新外部事件；规划实际呈现另一会话的预算与时间条件 |
| 普通 Agent 主链 | 13 / 13 | 文件、Shell、MCP、子任务、插话纠正、暂停恢复、附件与调度投递 |
| 记忆主链 | 11 / 11 | 实时学习、查询与原文读取、范围隔离、反馈及重启 |
| 邮件主动链 | 12 / 12 | 采集、历史条件、规则纠正、外部指令与提醒范围 |
| 完整工程回归 | 112 / 112 | 54.87 秒；包括交接回执丢失后暂停的两种实际领域状态 |
| 网页入口 | 通过 | 原生工作台的六项设置、可读对话选择、暂停状态；390 像素宽度无横向溢出、无 JavaScript 错误 |
| 构建与安装包 | 通过 | 网页插件构建、TypeScript 检查、wheel / sdist 新增入口；wheel 中 969 个已打包的来源文件逐字节匹配 |

最终空闲场景在业务模型调用账中记录 20 次成功调用，输入 96,441 tokens、输出 6,012 tokens；配置探测额外调用、本地向量编码和实际运行资源另计。这是一次完整受控流程的用量，不是每条主动消息的固定成本，也没有据此声称性能优化。

普通主链和邮件记录保留各自运行时的文件摘要；它们早于最后一处仅涉及空闲生产端暂停恢复的修正，执行、记忆和 Wake 文件没有随后变化。记忆主链也在该修正前运行。最终空闲场景的实现摘要与发布文件一致，新增暂停边界由完整工程回归覆盖。

故障注入发生在真实生产端把提案写入 Drift 之后、写下交接完成凭据之前。重放需保持同一提案、同一规划调用，新增规划调用为零；重启后恢复的研究可以分享，也可以根据历史判断已有同样结果而跳过。结算和投递分别核对。

两次跨会话完整通过的实验在恢复阶段做出了不同决定：一轮认为已有相同结果而跳过；最终一轮完成新交办的评估并确认一条投递。两轮都复用原提案与规划调用；“没有重复投递”限定于该提案的已确认消息数量，不等于已经具备跨主题的语义去重能力。

已有记忆主链、邮件主动链、普通 Agent 主链、网页入口和完整回归分别验收，不用这一条学习场景代替所有功能。当前是一个模型条件下的受控验证；没有无记忆配对干预，不能据此估计记忆净提升，更不能证明图普遍优于向量。它支持的是历史条件、规划、研究与投递可以在同一运行链路中协作。

## 开发观察

保留了初版验收的实际问题。第一次设置切换时，评测没有等待网页模块换代；另一次过早把已保存但尚未完成交接的 `planned` 状态当作终态。两者修正了评测等待条件，未改变模型的决定或隐藏原始记录。

恢复测试也观察到合理跳过：相同页面已有研究与投递，模型没有再发一遍。初版夹具预期一定增加通知，因而超时；后续按原生提案的实际终态、原规划调用是否复用、是否重复投递验收。旧超时仍保留，不能把通知数量当作主动交互效果。

另一轮是真实的生产端失败：模型把“这条只回复收到，不展开”理解为不能继续后台研究，并引用实际呈现的助手回复说明跳过原因；校验器又错误地仅允许用户消息，最终记为 `ValueError`，该轮只有 2 / 3 通过。修正后分别检查引用是否实际呈现、新提案是否有用户目标依据，并在规划中区分即时回复格式和目标是否仍然有效。目标完成、撤回及禁止后续研究的要求继续优先。失败记录与修正后的新实验分别保存。

恢复边界另用真实 Ledger OwnerState 和 Drift SQLite 验证：在领域写入成功而交接回执缺失时关闭自动思考，未领取提案被撤回；若 Wake 已经领取，则保留同一执行身份。这个确定性回归独立于模型场景，不能冒充一次新的模型实测。

完整回归曾出现 111 项通过、1 项失败：测试在投递结算之后立即读取另一独立消费者的游标，早于其提交。修正测试分别等待结算与归档消费，而非修改生产投递行为。浏览器初次定位也因帮助文字参与可访问标签而超时，改用标签前缀后通过；产品页面未因此更改。
