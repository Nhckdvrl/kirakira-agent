# 窗口规则：用三分之一的材料，保住全部可达性

本轮最明确的结果：**把"原文已在请求里"的候选从正文改成一行索引，初始材料由 2390 字降到 829 字（−65.3%），而 12/12 的参考值仍然留在回执准入的原文里——一次读取即可取回。** 这条结论是确定性的，不依赖模型表现。

全部证据可离线复核，**不需要 API 密钥、聊天模型、向量权重或私有工作区**：

```sh
uv run --frozen --no-sync python -m eval.memory_depth \
  --verify-existing docs/operations/evaluations/artifacts/2026-11-06-memory-window/evidence.json \
  --output /local-disk/eval/window-verification.json
```

## 固定条件

| 项目 | 条件 |
| --- | --- |
| 语料 | 固定生成的源导航夹具；16 题（首部事实、末页事实、更正、无答案各 4 题） |
| 对照 | 两臂同一语料、同一候选集（fused，4 个）、同一初始上限 2400 字、同一读取额度（最多 2 次、总计 6000 字） |
| 唯一差异 | `window-bodies` 给片段正文（窗口规则之前的呈现）；`window-index` 把每个候选都当成已引用，withhold 正文、对放得下的花一行索引（现在的呈现） |
| 索引 | 真实 Ledger、Learning、MessageConsumer；本地中文语义向量 512 维 |
| 模型 | step-5-preview，`reasoning_effort: low`，真实函数调用 |
| 规模 | 16 题 × 2 臂 = 32 次首轮试验 |

两臂的初始材料逐例不同，`initial_material_sha256` 已记录，不是同一份材料换个名字。

## 主结果：可达性不变，材料减少 65.3%

"参考值可达"的判定不经过模型：参考编号必须确实出现在**这次回执准入可读**的某条原文里。它直接回答窗口规则唯一真正的风险——省掉正文是把答案推迟了，还是把它丢了。

| 方案 | 参考值可达 / 12 | 初始材料含参考值 / 12 | 初始材料均值 | 读取次数 |
| --- | ---: | ---: | ---: | ---: |
| window-bodies | **12** | 4 | 2390 字 | 8 |
| window-index | **12** | 0 | **829 字** | 9 |

**答案没有丢，只是不再预先摊开。** 索引臂的初始材料里一次都不含参考值（0/12，按设计如此），但 12/12 的参考值仍在准入范围内的原文中，一次 `read_memory_source` 即可取回。代价是这一步要由模型主动走——它把工作从"预先注入"挪到"按需读取"。

## 工程不变量（同一次运行内核对）

| 检查 | 结果 |
| --- | ---: |
| 查询只读、重载后逻辑状态一致 | 通过 |
| 原文窗口重读逐字节一致 | 17 / 17 |
| **图重载后再重读仍逐字节一致** | 17 / 17 |
| 越权原文读取被拒绝（非准入消息、跨范围） | 2 / 2 |
| 离线复核全部行 | 32 / 32，`complete: true` |

越权拒绝这一项值得单说：索引臂的回执**不呈现任何正文**，准入只来自索引行。复核确认它既没有因此放宽读取（不在准入内的消息仍被拒），也没有因此失去读取能力（索引行命名的原文可读）。

## 答案层面的对照：本轮无法得出

严格答对为 window-bodies 2/12、window-index 1/12，两臂各有 8 次格式错误（模型未按要求返回恰好一个函数调用）。**这两个数字不能用来比较两臂。** 理由是确定性的：高强度重跑中 window-bodies 在四道首部题上 `initial_answer_span_present` 全为真——参考值就在它自己的材料里——却一题未答对，`reads` 全程为 0。基线臂在握着答案时都答不出来，就无法说明另一臂。

因此本报告不给出窗口规则的回答质量结论。suite 已就绪（`--suite window-v1`），换一个能稳定完成严格函数调用的 reader 即可得出；在那之前，可达性是能站得住的结论，答案质量不是。

这与本项目既有的做法一致：[取证深度实测](2026-10-22-memory-depth.md)同样以确定性的原文覆盖为主结果，同模型语义复核只作描述性证据。

## 这份报告没有证明什么

- 没有证明窗口规则对"答案本就在初始材料里"的日常对话同样无损——本夹具刻意把答案放在初始材料之外。
- 没有证明更弱或更不愿调用工具的模型能跟上索引行；相反，本轮的 reader 恰好不愿读取。
- 没有测量真实对话中的端到端延迟或费用变化；[免模型开销测量](../../../eval/cost_report.py)另给每轮注入、学习与检索的开销。
