# 记忆的取证深度与可靠性实测

本轮最明确的强项是：**召回片段提供线索后，沿同一出处继续读取原始消息，在材料上限内恢复片段外的事实，并保留可复读的证据范围。** 新实验量化这条能力，同时保留简单向量检索的相同读取能力，不预设图记忆一定更强。

公开历史的广泛质量结果继续见[既有记忆实测](2026-10-21-memory-runtime.md)。本轮是另一个受控组件实验，不替代 LongMemEval 分数，也没有运行外部记忆产品的同配置比较。

## 固定条件

| 项目 | 条件 |
| --- | --- |
| 语料 | 固定生成的 16 个项目、48 个完整闭段、96 条原始消息；长来源最多 12,284 字符 |
| 问题 | 首部事实、末页事实、旧决定被更正、没有答案，四类各 4 题 |
| 规模 | 16 题 × 5 个方案，80 次首轮试验；参考值不进入 reader 问题或检索索引标签 |
| 索引 | 实际 Ledger、Learning、MessageConsumer；固定本地中文语义向量，512 维 |
| 候选 | 同一编码器，同一原始经历集合，每方案最多 4 个闭段 |
| 材料 | 保留的序列化证据总计最多 6000 Unicode 字符，包含标题、时间、来源与窗口说明 |
| 静态方案 | 完整消息或片段，一次 reader 请求 |
| 按需方案 | 首次最多 2400 字符；reader 自主决定是否读取、读哪个已入选消息及偏移；最多追加两窗、三次 reader 请求 |
| 协议 | 实际 Models 函数调用；所有方案使用同一个最终回答函数；向量和图方案都有相同追加读取能力 |

历史确认回复是固定夹具，不是在线用户对话。索引没有用聊天模型抽取事实，构建使用 96 条消息的向量；这不代表 Markdown 档案的提炼也没有聊天模型成本。

这里的总材料上限是每题保留的证据，包括窗口间分隔符；多次请求会重新发送已有证据，累计输入和调用数另列。它不是“所有模型输入总共只有 6000 字符”。原文窗口来自正式 `MemoryQueries.source` 组件，不能读取父查询没有呈现的消息。完整过程见[证据](artifacts/2026-10-22-memory-depth/evidence.json)。

## 最稳定的量化结果：实际原文覆盖

“参考值原文到位”要求当前保留的真实字符串中出现固定参考编号，检查到具体片段；比“召回了一条带答案标签的消息”更严格。它仍然不等于模型答对。分母为 12 道可回答题；平均字符数及调用数使用全部 16 题。

| 方案 | 参考值原文到位 / 12 | 末页事实 / 4 | 更正末页 / 4 | 平均保留证据字符 | reader 调用 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 向量 + 完整消息 | 0 | 0 | 0 | 1201 | 16 |
| 向量 + 固定片段 | 4 | 0 | 0 | 5991 | 16 |
| 图融合 + 固定片段 | 4 | 0 | 0 | 5989 | 16 |
| 向量 + 按需原文 | 8 | 2 | 2 | 3351 | 25 |
| 图融合 + 按需原文 | **9** | **4** | 1 | **3367** | 24 |

在同一 6000 字符上限下，图融合方案加入按需读取后，参考值原文覆盖从 **4/12 增至 9/12**；平均保留的材料减少 **43.78%**。末页事实由 **0/4 增至 4/4**，说明模型确实能沿片段线索取回长消息末页，未靠扩大上下文窗口把整篇报告塞入模型。

向量检索加入相同能力也提高到 8/12。图融合在更正场景只有 1/4，低于向量按需方案的 2/4。因此，这个实验支持“可追溯、按需深入读取”的价值，不能据此证明图扩散普遍优于向量，或把 9/12 宣传为任务完成率。每类仅四题，是特意构造的取证压力场景，不代表真实使用分布。

完整消息方案会跳过放不进预算的长消息；它用于隔离呈现策略，不代表其它 RAG 系统只能这样处理。共享片段与共享追加读取的向量方案才是更有用的对照。

## 开销与出处

| 同一 16 题 | 图融合固定片段 | 图融合按需原文 |
| --- | ---: | ---: |
| reader 请求 | 16 | 24 |
| 平均累计重发的证据字符 | 5989 | 4562 |
| 实际输入 token 合计 | 60,436 | 52,844 |
| 实际输出 token 合计 | 3154 | 5431 |
| 追加原文读取 | 0 | 8 |

按需方案增加调用和输出开销；输入减少并不意味着总费用或总延迟一定减少。token 为这次实际模型用量，其他模型的编码、推理与价格都可能不同。

两个按需方案合计执行 **17 次原文读取**。全部窗口的来源、原文偏移、长度和序列化摘要重新核对，**17/17 复读一致**；重新加载消费者后仍为 **17/17**。全部 **80/80 初始材料**也重新渲染并逐字节摘要核对一致。新的原文读取不再编码、不重新扩散；已发布图的逻辑摘要在全部查询与读取后保持不变。一个未入选的真实消息和一个不同范围调用均被拒绝。

这些分别是材料完整性、已发布状态和组件重载的证据。完整 Runtime 重启、实际工具调用与原生投递由下面的独立验收覆盖，不把组件重载冒充整机恢复。

## 回答结果与边界

首轮机械规则要求包含当前编号、合法支持引用，并禁止回答字段出现旧编号。它误伤了“给出新值，同时明确解释旧值作废”的回答。原始分数保留：按上述顺序，12 道可回答题得分为 **0、4、4、6、3**；四道无答案题分别答对 **4、3、3、1、2**。三个 reader 协议错误也保留在分母：一次请求多个函数、两次没有返回要求的函数调用。

另做了一次独立的同模型语义复核，只看冻结的问题、参考值和回答，隐藏检索方案名称，不重跑 reader 或追加读取。80 条记录中，77 条有可复核回答，只有 **55 条获得有效的结构化 judge 结果**；无效结果保留为失败，没有选取重试后的分数。图按需方案的有证据且语义正确回答为 7/12，但这种同模型、存在无效评分的结果不适合作为主要宣传数字。本轮主要展示确定性核对的原文覆盖、材料预算和复读一致性。

开发阶段还保留了 38 条较早的自由 JSON 协议结果，其中 16 条格式解析失败；它们未混入 80 条函数调用主实验。之后只更换测量协议，没有按参考答案调整检索、改变候选上限或重做已完成的 reader。主实验的冻结源码与摘要随证据保存。

## 真实运行链路

本轮使用当前通用模型入口重新运行：普通主链 **13/13**，记忆主链 **11/11**，完整工程回归 **127/127**。

记忆主链覆盖真实渠道学习、服务与 RPC 一致、并发幂等、时间窗口、片段偏移、Agent 原文展开、历史更正回答、事件调查后投递、长记录末页读取、遗忘/恢复与完整 Runtime 重启。事件本身与近期上下文不提供参考答案，必须检查实际成功的记忆工具回执。

可以据此展示的产品能力是：**历史仍有原始出处；有限材料不足时可以继续取证；读取和重试不会悄悄重学；后续行动与投递有各自的持久回执。** 现有结果支持这种可靠的长期记忆使用方式，没有证明独有算法优势，也没有自动改变生产默认的候选与呈现策略。

复现、独立复核和统一模型条件见[评测入口](../../../eval/README.md#记忆取证深度)。实现与协议边界见[记忆架构](../../architecture/memory.md)。
