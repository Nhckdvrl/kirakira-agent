# 记忆是否真的改变了主动联系的判断：配对干预

日期：2026-11-07（运行于 2026-11-06 13:44 UTC 起）。真实聊天模型 `step-5-preview`、原生插件图、本地 TLS IMAP、本地会话投递。没有连接私人邮箱，也没有向外部收件人发送邮件。

这一轮的目的和[首轮 6 组](2026-10-21-mail-followups.md)不同。首轮报的是"有历史时判断对不对"（11/12）。这一轮问的是**因果**那一问：**把记忆拿掉，同一封邮件的判断会不会塌？**

## 为什么这个设计能回答因果

夹具 12 组，每组：

- **一封邮件，正文逐字相同**，两条臂完全一样。
- **两条相反的个人条件**，存在另一个会话里；`profiles[0]` 期望跳过，`profiles[1]` 期望分享。
- 两条臂：`present`（条件在记忆里）与 `withheld`（条件不存在）。

所以**同一组内，邮件本身不含答案**：正确的判断只能来自另一个会话里被召回的那条条件。这条内部有效性由回归守着（`tests/test_eval_harness.py`，检查正文不含决策措辞、两个 profile 方向相反且按位置打分）。

## 结果

| | 观察数 | 判断正确 | 对应历史被呈现 |
| --- | ---: | ---: | ---: |
| **记忆在**（present） | 18 / 24 | **16 / 18**　95% CI [0.67, 0.97] | **18 / 18** |
| **记忆拿掉**（withheld） | 19 / 24 | 7 / 19　95% CI [0.19, 0.59] | 0 / 19 |

两条臂都存在的 **17 对**上做配对精确检验：

| | |
| --- | ---: |
| 两臂都对 | 7 |
| 两臂都错 | 2 |
| **只有"记忆在"对** | **8** |
| 只有"记忆拿掉"对 | **0** |
| McNemar 精确检验 | **p = 0.0078** |

**八次分歧全部朝同一个方向，没有一次反向。** 这是本项目目前唯一一个**记忆改变了用户可见行为**的显著配对结果——不是设计性质，是行为差异。

## 必须一起说的三件事

**一、`withheld` 不是一个竞争方案，7/19 不是"对手的分数"。** 那条臂没有任何信息，所以它答不对是设计使然。它的作用是证明**邮件本身不足以决定**。看决策分布就清楚了：拿掉记忆后 19 次里 **13 次跳过、6 次分享**——模型退回"默认别打扰"，于是期望跳过的那些题白捡，期望分享的那些全错。这正是"无信息→默认行为"的指纹。

**二、掉样不是随机的，所以两臂的总分是有偏子集。** 48 次试验全部跑了，但 **11 次没有产出终态观察**：9 次在 240 秒验收上限超时，2 次模型侧错误。它们**集中在第 25–37 位**：

| | 前 24 次 | 后 24 次 |
| --- | ---: | ---: |
| 平均时长 | 177 秒 | 279 秒 |
| 失败数 | 3 | 10 |

最后 8 次（invoice、refund）又回到 71–273 秒且全部通过，所以不是单调变慢，是中段一段集中变慢后恢复——更像外部争用或服务端延迟，不像图增长。整组家族因此部分缺失（classsize 丢了 3/4，evening 丢了 3/4）。

**所以 16/18 和 7/19 这两个比例只能当描述读**；可用的是那 17 对，因为配对检验的单位就是对，整组缺失不会让存活的对失真。推广范围是**这套夹具**，不是某个总体。

**三、present 臂的两次错误是同一个方向。** `cloud_v1` 和 `region_v1` 都是"期望分享，实际跳过"——模型偏保守。首轮 6 组里唯一那次失败（region）也是这个方向。两轮独立出现同一失败模式，这不是噪声，是一个该记下的倾向。

## 这一轮之前还有一次无效运行

## 不声称什么

- 不是真实使用数据，所以"有用提醒与误打扰的比例"答不了。
- 12 组夹具是合成的，由我们自己写，决策形态不重复但不代表自然分布。
- 只有一个聊天模型，不能据此宣称其他模型有同样表现。
- `withheld` 臂不是基线，不能当作"比别的记忆方案好"的证据。它只证明邮件本身不足以决定。
