# 记忆的场景亮点：从线索继续查到原始细节

Kirakira 的记忆值得展示的一项能力是：**第一次召回只给出线索时，Agent 可以沿出处继续读原始经历，找回片段之外的具体事实。** 它适合核对过去的报告、研究记录与项目讨论，而不是要求用户重新提供整段背景。

本轮专门测这条能力。八道答案藏在长记录末页或中部的问题，只看片段得到 **0/8** 个有原文支持的正确答案；开放原文读取后得到 **5/8**，其中末页题 **3/4**。这是一个有边界的场景收益，足以支持继续打磨这条能力；评测目标是证明实际用途。

## 相同线索，能否继续查证

16 道固定合成题包含首部、末页、中部、无答案四组，各四题；两种方案共 32 次首轮试验。使用实际 Ledger、Learning、MessageConsumer、召回呈现与 `MemoryQueries.source`，向量为固定本地中文 512 维编码器，reader 经正式 Models 服务调用。

两组使用相同的图融合候选，每题最多四个完整闭段。**16/16 对初始材料逐字节一致**，上限均为 2400 Unicode 字符，包含来源、时间、窗口说明和分隔符。

| 条件 | 只看片段 | 允许沿出处读取 |
| --- | --- | --- |
| 初始材料 | 同一份 | 同一份 |
| 追加原文读取 | 不提供 | reader 自主选择，最多两窗 |
| 保留证据总上限 | 初始材料，不追加 | 6000 字符，包含序列化说明 |
| reader 请求上限 | 一次 | 三次 |
| 最终结果 | 凭证号或 UNKNOWN，附消息引用 | 相同协议 |

原文具有普通目录线索，例如“在报告末页”或“在报告中部”，不提供参考编号或精确读取偏移。八道重点题的答案均未出现在任一组的初始材料中。参考答案不进入检索索引或 reader 提问；reader 可以选择不读取，也可能读错。

这是关闭与开放一项能力的对照，追加读取允许更多材料和调用；它不属于等费用的检索算法比较。

## 结果看最终答案

正确要求回答字段等于参考凭证号，引用属于实际呈现的消息，并且引用对应的已读原文包含该编号。机械核对，不依赖另一个模型评分；格式错误保留为失败。

| 场景 | 只看片段 | 允许沿出处读取 |
| --- | ---: | ---: |
| 末页细节 | 0/4 | **3/4** |
| 中部细节 | 0/4 | **2/4** |
| 两类合计 | 0/8 | **5/8** |
| 无答案时回答 UNKNOWN | 4/4 | 4/4 |
| 首部控制题 | 0/4 | 0/4 |

重点八题中，追加读取后六题的原文值实际到位，五题最终答对；两者分别记录。三次未成功中，一次直接回答 UNKNOWN、没有继续读取，两次返回的函数调用数量不符合协议。其中一次格式错误发生在正确原文已到位之后，不能把它算成回答成功。

首部控制题是这套夹具的明显问题：虽然四题的参考值都已进入材料，两组均未正确回答。该位置只写“归档栏”，没有明确说明它是签收凭证；与有目录说明的末页和中部题不同，不能排除题义歧义。原结果保持 0/4，不用重点场景的收益掩盖控制题失败，也不据此宣称能够稳健理解任意字段。

### 一条可查看的实际过程

`long-tail-0` 的原始报告长 9659 字符，初次只呈现其 `[0:454]`，没有参考凭证。reader 根据末页线索选择 `[9000:9659]`，取得 `KF-EFE32D6236`，最后返回同一编号与该消息的引用。最终保留材料为 3145 字符，包含其他候选与说明，未把整份报告放进上下文。

这里的价值是**可以从一个历史线索继续追问同一个来源**。原文不是模型重写的摘要，窗口有明确的消息身份与字符偏移，事后可以复读。

## 收益的代价

以下只统计末页和中部的八道题，失败也在分母中。

| 指标 | 只看片段 | 允许沿出处读取 |
| --- | ---: | ---: |
| reader 调用 | 8 | 14 |
| 追加原文读取 | 0 | 6 |
| 平均保留证据字符 | 2390 | 3683.125 |
| 平均累计重发证据字符 | 2390 | 5475.625 |
| 实际输入 token | 13,815 | 32,978 |
| 实际输出 token | 3041 | 5022 |

它用追加材料与调用换取更深的取证；本轮没有测出降本或加速。模型、采样和工具协议也会影响最终回答，因此保留模型条件与全部首轮输出。

## 原始证据可以独立复核

全部 96 条合成原始消息逐条与实际 Ledger 对照后导出，32 份查询出处一起保存。公开快照重新构建的验证与直接读取实际 Ledger 的验证得到相同的 32 行结果。

- 32/32 初始材料的摘要、引用与字符数重现一致。
- 全部八次追加窗口逐条核对原文、偏移、序列化摘要与材料上限。
- 16/16 对初始材料一致；32 个答案按原文重新计分一致。
- 原生组件验收中，八次原文读取在消费者重载前后复读一致；查询与读取未改变已发布图，两个越界读取被拒绝。

公开[原始证据](artifacts/2026-10-22-memory-scenarios/evidence.json)含完整合成历史、查询出处、冻结的 reader 源码、回答、调用用量与失败；[离线复核结果](artifacts/2026-10-22-memory-scenarios/verification.json)不调用聊天或向量模型。

本轮记忆回归 **17/17** 通过。离线复核另外拒绝了五种篡改：修改原文、修改分数、修改读取窗口摘要、重复试验和修改冻结的模型回答；正常证据重算通过。它们验证复核程序，不计入上面的回答成绩。

开发阶段另有一批 32 次诊断试验，按需组使用较小初始片段后意外直接包含答案，**没有任何追加读取**。它能说明片段选择影响结果，却不能归因于原文展开。本轮据此固定相同初始材料；诊断原始记录一并保留，不混入上表或改写成成功展示。

## 其他已经有依据的记忆特色

**过去的条件可以影响后续行动。** 六组相同邮件、不同历史条件的[受控实验](2026-10-21-mail-followups.md)中，12 次调查都呈现了相应原始条件，11 次分享/跳过符合预期。它支持预算、安排和许可参与今天的处理；召回正确但误解地域条件的一次仍保留。用户澄清后的复查作为独立干预，不改首轮成绩。

**长期使用仍保留可核对的出处。** [学习与恢复实验](2026-10-21-memory-runtime.md#学习与恢复的一致性)在 300 回合、第 87 回合崩溃的条件下补学七回合未发布尾部，最终逻辑状态与逐回合发布、完整重建一致。真实工具、事件投递与完整 Runtime 重启另有记忆主链验收。恢复一致性证明运行约束，与回答质量分别解释。

这几项共同服务于个人 AI 伙伴：过去的经历能继续查，历史条件能用于现在的行动，工作中断后依据仍在。它们是本项目已经做出并能够演示的能力；本轮没有比较外部记忆产品，也没有隔离图扩散相对于向量的独立收益。

后续优先检查目录线索缺失、线索位置错误、多份相似报告及读取之后的协议失败。公开历史题继续用于检查退化，新增实验围绕这些具体场景展开。
