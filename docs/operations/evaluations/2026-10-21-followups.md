# 从历史约定到持续跟进

日期：2026-10-21。本文记录 `4737622` 对应版本在真实模型、原生插件图、HTTP 信息源和确认投递链路上的验收。后续代码与邮件接入见[新的实测报告](2026-10-21-mail-followups.md)。输入是受控场景，不代表真实用户的通知有效率。

这轮要证明的行为是：用户在不同对话修改项目安排后，新发布或网页变化仍按当前安排处理；需要时可以展开原始长文核对；每条结果能够追溯到调查和实际投递。

真实模型通过通用 `openai-compatible` 驱动接入，模型标识不参与业务判断。本次调用模型为 `step-5-preview`，只使用 `https://api.stepfun.com/step_plan/v1`；上下文窗口 32,768，输出预算 4,096，推理设置 low。中文向量为固定的 BGE small zh v1.5 / 512 维本地资产。配置与逐次调用数量在 JSON 中保留，密钥和登录信息不进入材料。

三个最终跟进运行共记录 87 次远程聊天调用，输入 611,276 tokens、输出 14,206 tokens；包括配置探测、历史生成和调查，不能与单次召回成本混用。原生聊天计量不包含本地向量调用，不把其零值解释成未计算向量。各调查耗时也不能当作公开线上延迟基准。

## 具体验证了什么

### 关注理由可以延续，当前决定需要重新核对

受控历史包括：

1. 青禾项目使用云杉库，最初不允许升级 v2，只希望收到与离线数据有关的变化。
2. 另一个会话更正：允许升级，但必须先有加密离线备份，再在隔离副本验证；负责人也有明确记录。
3. 另一个项目存在相似的升级讨论，安排与青禾不同。
4. 外部来源先发布纯排版更新，再发布会原位转换缓存格式的公告。外部公告没有个人项目安排或答案。

三次最终运行都跳过了排版更新，并对格式变化产生确认投递。两个隔离项目运行都采用后来的安排，核对到对应历史消息，未读取另一个隔离项目的来源。通知收件对话保持全局范围，调查会话仍属于青禾，说明通知位置没有替换记忆范围。

全局运行虽然采用了更正后的加密备份与隔离验证要求，却额外复述了另一个项目的人名和安排。该项按照预先检查的“不得出现无关负责人”条件判失败，未放宽评分。它没有把别人的安排套用到青禾，但仍暴露无关信息混入的问题。共享记忆下的相关性控制和输出收敛需要继续改善；隔离项目通过不等于全局模式已经解决该问题。

### 原文展开参与真实主动调查

长原文案例有 20,317 字符，最后签字人的信息仅出现在末尾。跟进配置明确要求使用摘录并核对末尾，外部事件不含签字答案。

实际调查先通过记忆工具取得出处，再调用 `read_memory_source` 读取原始消息的 **[18,317, 20,317)** 字符，随后按核对到的签字人分享并确认送达。原文读取证明和父召回回执进入 Ledger，时间线展示实际范围；重启后保持同一事件与证据。

这是工具可用性、出处约束和完整链路的证据。它没有证明模型会自行选择最优检索策略，也没有完成等总调用预算的策略比较。独立记忆主链另有 20,320 字符的长文核对通过，不能将两个有明确提示的案例当作公开长文本质量分数。

### 明确委托与兴趣相似度分别记录

排版案例的实际语义兴趣约 0.5184，格式变化约 0.5894。用户明确跟进的更新通过独立调查请求接纳，兴趣分没有被改高；是否分享仍由调查决定。它解决了“已经要求跟进，却因为通用兴趣阈值未开始调查”的执行问题。

在 CI 中，两个兴趣分为零的明确请求仍可逐条调查，且只消费实际领取的条目；真实模型验收继续检查最后是否正确分享或跳过。明确委托不等于无条件发送。

### 页面变化先有事实，再交给 Agent 判断

网页采集使用静默基线、关注区域与前后差异。CI 验证导航变化不产生事件，费用从 100 降到 80 又恢复 100 会产生两个不同版本；重复读取不再次提交。指定区域消失时保留旧快照和版本水位，错误不会变成内容删除。

网页真实模型回放按同样的历史、更正和项目隔离验收，9 / 9 通过。普通网页、订阅源都走 EventMail → Wake → 原生工具与记忆 → Delivery，不另建执行队列。

公开读取另验证了 CPython 发布 Atom 和 Python 官方博客 Atom，以及 Python 下载页的指定区域；下载区域有 13,538 字符。整篇 RFC 文本因关注区域超过 24,000 字符被明确拒绝，该失败保留在材料中。它说明当前范围上限，不证明支持任意网页、登录账户或 JavaScript 渲染。

### 可检查的送达与停止控制

- 初次成功抓取只建立基线；缓存命中与重复版本不新增调查或通知。
- 事件系统先返回持久回执，采集器再推进游标。CI 在两个提交之间制造中断，上游移除条目后仍能恢复原接纳引用。
- 时间线沿事件结算引用查询精确 Delivery 确认；没有用消息文案相似或猜测元数据代替回执。
- 原始对话、成功记忆读取、继续展开原文、分享/跳过和确认投递均可检查。
- 暂停返回后不再抓取新内容；已接纳的工作可以完成。送达后的“有用/无关”反馈和暂停状态经过真实重启保持。
- 活动 WAL 中的运行查询使用原生只读快照，离线交接核验继续保留独立入口。

绑定历史的跟进在本次调查成功读取记忆前不能提交分享或跳过；无法读取时仅允许记录依据不足的跳过。模型没有按要求返回结构化工具时，普通回答保留为未完成输出，在原 Task 的原有步数限制内继续纠正，不伪造工具或投递记录。成功读取的前置条件仍不能保证最终语义正确。

浏览器验收通过真实宿主发布的模块访问实际后端，核对原始消息、投递、反馈、网页创建、立即检查、暂停、HTML 转义、390 像素宽度、深色主题和卸载监听释放。缺少模块身份的请求被拒绝为 403，非法跟进标识为 422。宿主工具页挂载由支架提供，未将这项结果宣称为所有工作台登录与导航流程的完整认证。

## 保留的失败与后续判断

开发回放还暴露过兴趣门槛阻断明确请求、运行查询误用离线 WAL 核验、沿用旧约定、普通文字提前结束调查、界面缺少依赖声明等失败。JSON 保留这些开发结果；一条在源码修改期间重启失败的开发运行标记为无效，不计入最终质量分母。最终版本还保留上面的全局无关信息失败。

目前能够展示的长处是：**新变化可以结合跨会话更正采取行动，证据能继续回到原始长文，投递和恢复可核对。** 这些结果支持当前的长期个人工作方向，不证明相对所有个人 Agent 全面领先。
