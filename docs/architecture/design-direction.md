# 长期工作、记忆与主动行为的设计依据

调研日期：2026-10-21。以下是读取公开项目文档和实现后提炼的设计输入，不是能力排名，也不代表已把这些机制全部实现。只有在本项目中做过的实验，才进入本项目的结果表。

## 从其他实现学什么

| 项目与一手材料 | 具体机制 | 对本项目的启发 |
| --- | --- | --- |
| [Pi](https://pi.dev/) 与 [Pi Durable](https://earendil.com/posts/pi-durable/) | 小内核、扩展、自定义上下文；长期执行已有专门实验 | 解释为何保留完整 Runtime 以及复杂性换来的行为，不能把持久化本身称作独有优势 |
| [Maka](https://github.com/apache/maka) | 执行日志是运行事实，界面和恢复是其投影；评测公开逐任务记录 | 评测层管理实验与评分，执行仍交给正式链路；报告失败、条件和分母 |
| [OpenClaw Memory](https://github.com/openclaw/openclaw/blob/main/docs/concepts/memory.md) | 档案、每日记录、后台整理、来源准入与可追溯提升 | 记忆写入资格、日常召回、长期提炼需要分别定义，后台整理不应把外部文字自动升级为主人指令 |
| [Letta Code MemFS](https://github.com/letta-ai/letta-code/blob/main/src/agent/prompts/letta_local_memfs.md) | 核心记忆与外部记忆分层；提交的版本参与后续上下文编译 | 明确“文件已写入”和“当前请求已使用”的区别，保持少量常驻档案与按需历史读取 |
| [Graphiti 的边记录](https://github.com/getzep/graphiti/blob/main/graphiti_core/edges.py) | 事实有效起止时间与记录过期字段分开 | 消息时间筛选不能冒充事实时态；真正的事实有效期需要抽取、更正与消歧协议 |
| [Mem0 实现](https://github.com/mem0ai/mem0/blob/main/mem0/memory/main.py) | 默认可通过模型抽取事实，并处理新增与更新；也有不推断的写入路径 | 事实档案与经历检索是不同表示；比较时要计入抽取、更新与读取成本，不能只比较一次向量查询 |
| [Hindsight](https://github.com/vectorize-io/hindsight) | retain、recall、reflect 分离，记忆类型与 mental models | 观察、推断和长期总结应能区分，跨场景的推断不能替代原始证据 |
| [Mastra Observational Memory](https://mastra.ai/docs/memory/observational-memory) | 用观察与后续压缩组织长历史上下文 | 记忆效果与上下文大小应一起测，压缩后遗漏关键事实也需要列入失败分析 |
| [Hermes Memory](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/features/memory.md) | 有容量限制的常驻记忆与会话搜索协作，另有程序性 Skill | 不把所有经历塞进常驻 Prompt；稳定偏好、具体历史和可复用操作方法分别组织 |
| [Nanobot Automations](https://github.com/HKUDS/nanobot/blob/main/docs/automations.md) | 明确区分定时、心跳与事件触发的自动化入口 | 主动行为首先需要可靠触发、停止和交付语义；“会主动”还不是通知有用的证据 |
| [Deep Agents 架构](https://github.com/langchain-ai/deepagents/blob/main/libs/ARCHITECTURE.md) | Harness middleware、后端与底层图 Runtime 分工 | 扩展行为、模型循环和持久执行分别有 owner；增加一个功能不应再造另一套运行权威 |

这些系统已经覆盖记忆、主动执行、扩展和持久运行的大部分组合。增加插件数量或重新命名现有机制，无法建立可信的辨识度。

## 当前选择

Kirakira 当前的工作定位是：**面向长期个人工作，让过去的经历持续参与今天的判断和行动。**

这个定位需要由“记录过去、按证据理解变化、据此处理新事件、接续未完成工作”的实际行为支撑。记忆、主动任务和持久执行分别承担其中一部分；插件数量和检索总分只是实现与评测信息，不能单独替代用户价值。

优先把“过去确认的项目决定，如何影响今天的行动”做完整。它要求同时处理历史更正、不同项目的相似信息、原始证据、当前事件和投递结果，能够用具体场景检查。

目前实现上的投入包括：程序和工具共用的记忆读取合同、带时间的原始材料、固定预算和可重试出处、沿入选片段展开原文，以及从历史对话到新事件提醒的贯穿验收。它们是可检查的工程交付；对外表达不把这些常见机制声称为独创。

为保留原文的纠错能力，选择在消息账本上建立派生图和档案，而非让摘要覆盖原始经历。代价是存储、来源核验和重建协议较完整，仍需要认真控制模型实际收到的材料。

为维持同一执行语义，对话、事件调查和后台任务共用模型、工具、记忆与投递服务。代价是插件生命周期、权限和取消处理复杂；必须用恢复和中断实验支撑这项取舍。

## 定位落实到了哪里

| 用户得到的价值 | 当前实现与证据 | 尚未完成的产品工作 |
| --- | --- | --- |
| 以前确认过的安排能用于今天的工作 | 历史更正、相似项目干扰、新事件调查和投递已贯通；事件本身不含参考答案 | 默认可用的真实事件来源，以及连续多日的实际使用验收 |
| 能核对记忆为何影响这次判断 | 查询保留入选来源、时间和范围；片段不足时可展开原文，20,320 字符的记录中成功读回结尾签字人 | 把项目决定、依据、更正与后续行动串成易用的集中查看路径 |
| 工作中断后可以接着做 | 工具与查询具有持久身份；失败会话恢复后沿用已完成的原文工具结果；300 回合崩溃重放状态一致 | 更长周期的任务使用记录和面向用户的恢复体验 |
| 主动消息值得占用注意力 | 当前能调查、跳过和去重，投递有回执 | 真实通知有效率、误打扰率、用户反馈闭环；空闲提案生产者仍缺失 |

因此，当前已经有支持定位的运行闭环；完整的日常产品体验仍需补齐。现阶段不把“主动调查可运行”写成“已经懂得何时不打扰”，也不把受控场景通过当成长期使用效果。

## 记忆的优秀之处如何证明

评价目标是找出适用场景与设计收益。基线用来分辨收益来自哪里，以及为它付出了什么代价；无需先取得所有题型的最高总分。

- **历史更新与时间信息可用。** 当前 42 题子集中，融合加片段在知识更新为 6/6、时间推理为 5/6；同时保留其在其他题型上的损失。这支持小样本中的具体能力，不构成图机制普遍优越的结论。
- **记忆可以回到原始证据。** 原消息不被摘要覆盖，片段带原文范围，并可沿父查询展开。实时场景已经验证从短片段读取长记录结尾；它证明核对路径可行，不能直接算作固定预算检索成绩。
- **情景图学习无需聊天模型抽取事实。** 完整闭段经固定向量空间进入学习循环；公开历史实验按题累计学习 10,248 个闭段。这里说的是情景图，Markdown 档案提炼的模型成本另计，本地编码与图计算也有成本。
- **长期运行时状态可检查。** 查询不改写学习图，查询重试保留出处，崩溃尾部重放与完整重建状态一致。它们支撑可恢复的长期记忆，不替代语义质量指标。

这些能力可以共同支撑 Kirakira 的长期工作体验，不必声称每项都是独有机制。要进一步证明关联图本身的额外价值，应分析它补回了哪些向量候选遗漏的关键经历，并验证这些经历是否实际改善行动或回答。

## 用什么结果决定下一步

| 假设 | 实验 | 支持它所需的证据 |
| --- | --- | --- |
| 图式联想补足单次向量搜索缺失的经历 | 完整干扰历史、固定候选与字符预算，分开记录通道和呈现内容 | 补全通道实际提供缺失的关键消息，并改善 reader 回答；不能只看更多命中 |
| 更合理的候选选择改善长期记忆 | 固定图上比较既有通道、交替排列、排名融合；另留独立题目 | 提升在独立题目仍存在，且没有通过增加预算获得 |
| 历史项目约束能改善主动提醒 | 事件不携带答案，要求从以前确认的记录核对并投递 | 提醒同时符合更正后的安排与约束，来源可查，事件重投不增加通知 |
| 通知更克制 | 长期带用户反馈的事件集，统计应发、应跳过和实际投递 | 有效通知率和误打扰率；当前受控跳过场景不能替代真实用户指标 |
| 同一运行链路可接续工作 | 中断、重启、已成功工具效果与查询重试 | 不重复产生既有副作用，继续使用同一出处和权限 |

独立题目由固定 ID 哈希顺序提前划分，不能根据答题结果挑选。修改方案后保留失败题，并在独立集合再测。公开数据子集只报告子集成绩，不包装成完整基准排名。

## 如何展示

首页保留现有视觉设计，用一个可运行的长期项目场景解释用户得到什么。技术页解释记忆和执行的取舍，验证页公开实验条件、原始逐题结果与限制。

项目介绍中的模型保持可配置。具体实验仍记录实际 reader、编码器、judge 和驱动，因为这些条件会影响结果；同一模型的两个驱动路径也不能写成两个模型泛化实验。

当前结论与后续投入由[验证入口](../operations/verification.md)和[交付路线](../status/roadmap.md)共同更新。
