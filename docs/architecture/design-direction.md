### 先做成哪些事情

这轮选择的第一条完整路径是：**持续跟进一件已讨论过的事，在新信息出现时结合当前安排决定是否联系用户。** 已有发布订阅和静态网页接入，使用同一套历史范围、调查、来源核对与确认投递。它是可演示的工作流，不声称其他产品没有。

| 场景 | 用户实际得到什么 | 接入和下一步设计 | 验收方式 |
| --- | --- | --- | --- |
| 项目发布、申请公告、页面条款 | 相关变化及其对已有安排的影响 | **已实现基础链路**：RSS / Atom、GitHub 发布、静态网页和区域差异；登录页面与浏览器渲染待补 | 导航噪声不入队、真实恢复也能检测、过期约束不复用、通知能回到原文和实际投递 |
| 需要处理的邮件 | 哪封需要我决定、截止何时、与哪个项目有关 | **已实现只读 IMAP 链路**：原生账户设置、文件夹与发件人/主题筛选、UID 检查点、同批线程合并；本地 TLS 实测，具体服务商账户待验收 | 安静基线、积压分批、重复副本、更正与取消、只读协议、UID 身份变化、规则修改和重启分别验收 |
| 等待回复与截止日 | 哪些承诺有风险、是否值得追问 | 从用户确认的事项建立跟进；把“暂缓”“已完成”“不再跟进”写成明确状态；邮件或日历只提供事实 | 已取消事项不再提醒；跨时区与改期正确；没有新证据时不假称收到回复 |
| 每日工作简报、会议前准备 | 合并当前项目变化与待办，减少重复查找 | 日历和邮件接入后按时间窗生成摘要；普通更新聚合，急事单独提醒；链接到每条原始材料 | 摘要遗漏、重复提醒、过时事项和每次打扰包含的有效信息分别计分 |
| 读过的研究与资料持续跟踪 | 新发现与过去的问题、决定建立关联 | 已有记忆召回与原文展开；需补真实资料接入、持续问题状态、一次有效流程到 Skill 的转化 | 相同模型与调用预算，对照无记忆、向量、关联召回；最后答案与行动单独检查 |

邮件先做“发现、判断、准备”，发送回复作为独立授权能力；当前实现提供可配置的只读 IMAP，尚未连接用户的私人邮箱。IMAP 的 UIDVALIDITY/UID 留在连接器中，统一转换为已有事件，不增加第二套执行队列。邮件正文属于外部信息，不能因为含有“请立即转发”“忽略之前要求”就获得发送或用户规则写入资格。

### 怎样判断这些设计有用

要测三个不同问题：采集是否漏掉变化，判断是否符合用户当时的安排，通知是否真正有用。分别报告原始变化数、成功接纳数、调查数、分享/跳过数、确认送达数和有效反馈数；不能把其中任意一个比例替代其他比例。

连续使用时，另外统计每用户日的打扰次数、重复通知、错误跳过、来源失败的可见性，以及有用提醒中实际需要行动的比例。只有用户标注和独立回放集到位后，才比较“克制主动”的效果。当前受控回放验证流程与具体约束，不能作为真实用户满意率。

这也限定当前定位的力度：可以展示“过去的项目更正如何改变今天的提醒”和“一个提醒如何核对原文”；尚不能宣称更懂用户、通知最准或全面领先。邮件、会议和研究场景的优先级来自实际日常需求，后续由留存使用和失败数据调整。

## 当前选择

Kirakira 当前的工作定位是：**能结合历史、接受纠正并重新判断的持续跟进 Agent。**

具体体验是：把已讨论过的事交给它跟进，出现新信息时结合个人背景判断；发现理解有偏差，可以修改对应事项的规则，并对原内容重新判断。每次结果能查看当时使用的历史、规则和真实投递。这个体验比“拥有长期记忆”更具体，也不把常见架构组件宣称为独创。

这个定位需要由“记录过去、按证据理解变化、据此处理新事件、接续未完成工作”的实际行为支撑。记忆、主动任务和持久执行分别承担其中一部分；插件数量和检索总分只是实现与评测信息，不能单独替代用户价值。

优先把“过去确认的项目决定，如何影响今天的行动”做完整。它要求同时处理历史更正、不同项目的相似信息、原始证据、当前事件和投递结果，能够用具体场景检查。

目前实现上的投入包括：程序和工具共用的记忆读取合同、带时间的原始材料、固定预算和可重试出处、沿入选片段展开原文，以及工作台中的[持续跟进](../handbook/followups.md)。用户可以从原始对话建立订阅、查看调查与投递、评价结果并暂停采集。这些是可检查的工程交付；对外表达不把这些常见机制声称为独创。

### 邮件实验如何收敛定位

六组受控邮件覆盖预算、费用、时间、工作方式、地域与使用许可。每组邮件完全相同，只有另一个历史会话中的个人条件不同。带历史的 12 次调查中，11 次选择了预期的分享或跳过，12 次实际呈现了相应的原始条件。它说明历史在这些任务中可以参与行动选择，不能证明图结构优于向量或真实用户通知更有用。

保留的一次错误更有设计价值：用户说自己没有地域限制，模型虽然找到了原话，却误读成服务商必须覆盖所有地域，跳过了本可考虑的美国区域方案。后续用户明确澄清主语，再以新规则复查同一封邮件，得到了一条确认投递；旧误判和原文仍在。这是一次有人工干预的纠正，不能把首轮成绩改成 12 / 12。

因此继续投入的特色是**可纠正的持续判断**：情景记忆恢复背景，显式规则保留用户当下要求，原内容支持复查，结果保留版本关系。不是把所有反馈自动学习成永久偏好，也不是声称 Agent 不会误解用户。功能与局限均有[逐项实测](../operations/evaluations/2026-10-21-mail-followups.md)。

### 由实测确定的设计

**明确请求独立于兴趣相似度。** 实测中，用户已选择跟进的更新，语义兴趣约为 0.52，仍低于通用兴趣池的调查阈值。现在把“逐条调查”和“兴趣筛选后调查”公开为选择：前者承接明确请求，后者保留环境感知式筛选。调查资格、兴趣分和最后是否发送分别记录，不通过抬高相似度制造效果。

**最初依据和当前决定分开。** 跟进保留原始关注理由，调查按消息时间和更正关系检查当前约束。首轮模型已经出现过“召回包含更正，但提醒仍使用旧安排”的失败；因此结果验收同时检查实际通知内容，不能只检查召回是否命中。

后续复测还发现，模型会不检索历史就沿用旧安排，并可能因此错误跳过。现在把历史核对放进终止决策工具的前置条件：绑定历史对话时，分享和跳过都需要本次调查的成功记忆读取；无法读取时只能跳过并说明依据不足。事件只携带原始对话引用，正文仍回到 Ledger 读取，避免在候选中重复注入旧安排。前置检查本身不等于语义正确，报告继续核对最后的实际行动。

**记忆范围独立于通知位置。** 调查继承发起对话的范围和召回策略。统一收件会话只决定通知发到哪里，不能替换原项目的隔离图。每次调查只处理同一上下文的候选，明确请求逐条领取，未领取条目不被提前标为已处理。

**显式规则独立于经历排序。** 回归发现，用户已经修改了关注规则，但修改来源不属于情景图的学习白名单；调查反复搜索旧经历，无法核对新规则。现在在接纳调查时按来源、版本与原始用户文字核对规则记录，并与所采用的规则版本一起固定。情景图继续恢复背景，不承担精确配置读取；外部正文不能伪造该用户记录。

**重新判断保留旧事实。** 手动复查复制已接纳的原内容与原始发布时间，关联当前规则和之前版本；它不是一次新的来源抓取。相同内容与规则复用回执，旧来源、旧判断与采集水位保留，暂停采集不妨碍用户明确要求复查。这让“纠正 Agent”成为可操作流程，而不仅是要求它下一次记住。

**核对沿真实回执进行。** 时间线从来源端口读取原事件及状态，从已接受调查读取成功工具结果，沿事件结算引用读取精确投递确认。界面无需猜测文案或读取其他插件的数据库。运行中查询使用 WAL 感知的只读快照；离线交接仍使用独立核验入口。

为保留原文的纠错能力，选择在消息账本上建立派生图和档案，而非让摘要覆盖原始经历。代价是存储、来源核验和重建协议较完整，仍需要认真控制模型实际收到的材料。

为维持同一执行语义，对话、事件调查和后台任务共用模型、工具、记忆与投递服务。代价是插件生命周期、权限和取消处理复杂；必须用恢复和中断实验支撑这项取舍。

| 以前确认过的安排能用于今天的工作 | 对话建立 RSS / Atom / GitHub 发布、静态网页与 IMAP 跟进，历史更正、相似项目干扰、新事件调查和投递已贯通 | 连续多日的实际使用验收，以及具体邮箱服务商接入 |
| 理解有偏差时可以修正并重新判断 | 原始用户规则、版本绑定、同一内容复查与回执去重；保留一次真实模型误判及人工澄清后的结果 | 多轮纠正的独立保留集、跨事项冲突与更自然的对话入口 |
| 能核对记忆为何影响这次判断 | 查询保留入选来源、时间和范围；片段不足可展开原文；跟进时间线集中查看原对话、新内容、成功读取和实际投递 | 大型实际项目中的操作体验与长期效果 |
| 工作中断后可以接着做 | 工具与查询具有持久身份；失败会话恢复后沿用已完成的原文工具结果；300 回合崩溃重放状态一致 | 更长周期的任务使用记录和面向用户的恢复体验 |
| 主动消息值得占用注意力 | 当前能调查、跳过和去重，投递有回执；已送达条目可反馈有用或无关，并暂停后续采集 | 真实通知有效率、误打扰率、反馈如何改变后续策略；空闲提案生产者仍缺失 |

因此，当前已经有支持定位的运行闭环；完整的日常产品体验仍需补齐。现阶段不把“主动调查可运行”写成“已经懂得何时不打扰”，也不把受控场景通过当成长期使用效果。

## 记忆的优秀之处如何证明

评价目标是找出适用场景与设计收益。基线用来分辨收益来自哪里，以及为它付出了什么代价；无需先取得所有题型的最高总分。

- **历史更新与时间信息可用。** 当前 42 题子集中，融合加片段在知识更新为 6/6、时间推理为 5/6；同时保留其在其他题型上的损失。这支持小样本中的具体能力，不构成图机制普遍优越的结论。
- **记忆可以回到原始证据。** 原消息不被摘要覆盖，片段带原文范围，并可沿父查询展开。实时场景已经验证从短片段读取长记录结尾；它证明核对路径可行，不能直接算作固定预算检索成绩。
- **情景图学习无需聊天模型抽取事实。** 完整闭段经固定向量空间进入学习循环；公开历史实验按题累计学习 10,248 个闭段。这里说的是情景图，Markdown 档案提炼的模型成本另计，本地编码与图计算也有成本。
- **长期运行时状态可检查。** 查询不改写学习图，查询重试保留出处，崩溃尾部重放与完整重建状态一致。它们支撑可恢复的长期记忆，不替代语义质量指标。

这些能力可以共同支撑 Kirakira 的长期工作体验，不必声称每项都是独有机制。要进一步证明关联图本身的额外价值，应分析它补回了哪些向量候选遗漏的关键经历，并验证这些经历是否实际改善行动或回答。

## 用什么结果决定下一步

| 假设 | 实验 | 支持它所需的证据 |
| --- | --- | --- |
| 图式联想补足单次向量搜索缺失的经历 | 完整干扰历史、固定候选与字符预算，分开记录通道和呈现内容 | 补全通道实际提供缺失的关键消息，并改善 reader 回答；不能只看更多命中 |
| 更合理的候选选择改善长期记忆 | 固定图上比较既有通道、交替排列、排名融合；另留独立题目 | 提升在独立题目仍存在，且没有通过增加预算获得 |
| 历史项目约束能改善主动提醒 | 事件不携带答案，要求从以前确认的记录核对并投递 | 提醒同时符合更正后的安排与约束，来源可查，事件重投不增加通知 |
| 通知更克制 | 长期带用户反馈的事件集，统计应发、应跳过和实际投递 | 有效通知率和误打扰率；当前受控跳过场景不能替代真实用户指标 |
| 同一运行链路可接续工作 | 中断、重启、已成功工具效果与查询重试 | 不重复产生既有副作用，继续使用同一出处和权限 |

独立题目由固定 ID 哈希顺序提前划分，不能根据答题结果挑选。修改方案后保留失败题，并在独立集合再测。公开数据子集只报告子集成绩，不包装成完整基准排名。

## 如何展示

首页保留现有视觉设计，用一个可运行的长期项目场景解释用户得到什么。技术页解释记忆和执行的取舍，验证页公开实验条件、原始逐题结果与限制。

项目介绍中的模型保持可配置。具体实验仍记录实际 reader、编码器、judge 和驱动，因为这些条件会影响结果；同一模型的两个驱动路径也不能写成两个模型泛化实验。

当前结论与后续投入由[验证入口](../operations/verification.md)和[交付路线](../status/roadmap.md)共同更新。
