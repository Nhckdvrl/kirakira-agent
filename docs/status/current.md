# 当前状态

Kirakira 的定位是陪伴型、助理型、主动交互型的个人 Agent，面向日常交流、兴趣、学习、生活与工作。持续跟进、原文核对和可纠正的判断是具体工作流；整体体验和未完成部分见[产品定位与设计](../architecture/design-direction.md)。

Kirakira 使用同一个 Runtime 管理对话、记忆、工具、项目和后台执行。
模型由可替换的 driver 提供；Python、SDK 与评测使用同一个 `.venv`。
工作台已接入记忆召回预算、长期档案、对话与子任务、定时任务、后台通知、命令和 Web 工具的原生设置；参数保存经插件配置换代生效，留空可恢复默认。入口见[运行参数](../handbook/start.md#运行参数)。

网页与 SDK 已支持[显式跨会话接续](../handbook/start.md#接续其他会话)：只发送引用坐标，按需翻阅原文、展开长消息，并重新核对后来变更的决定。
网页切换保留健康连接，主动调查的近期上下文按尾页读取，历史召回兼容查找先筛选出处；实际效果与限制见[本地体验实测](../operations/evaluations/2026-10-31-runtime-experience.md)。
10 月 31 日延迟调查的最终部署健康、来源与数据保留检查通过，但当轮 SDK/CLI 六项真实请求均遇到 HTTP 429，Telegram 验收也在配置限流后退出；NFS 新工作区首轮仍有 26.008 s 慢例。工程检查通过不等于实际回答恢复，早期成功与最终失败按阶段保留；后续工作流功能验收另列，不替代这批入口延迟测量。

个人助理工作流继续补上两个日常断点：[已有邮件回查](../handbook/followups.md#只读邮件跟进)允许明确授权检查指定文件夹最近 1—50 封实际邮件，再继续增量跟进；[后台交办与回访](../handbook/start.md#把事情交给后台继续正常聊天)可以查询已经结算的任务，分别核对工作结果和通知回执。邮件发现截止日期与用户确认登记提醒分别验收，实测结果和开发失败见[邮件、提醒与后台回访](../operations/evaluations/2026-10-31-personal-workflows.md)。

11 月 1 日按用户要求停止常驻服务，新修补仅在隔离工作区验收，未部署。最终后台完整流程 6/6，邮件两个内容判断和两个提醒登记／恢复步骤均通过，通用主链 13/13，工程回归 177 项通过；旧的限流失败仍保留。邮件提交前的内容可恢复，暂停不新提交；回访停止或失败等待下一次真实输入，已完成结果不占执行名额。最终普通聊天仍出现 16.897 s、后台确认 45.022 s 慢例，功能通过不代表延迟已解决，也未验证未来邮件提醒实际送达。

同日继续补齐长期运行边界：摘要按消息身份累计覆盖，旧来源未结束时仍能压缩后续完整历史；Markdown 档案保存消费检查点，模型失败可暂停后恢复；任务耗尽步数后能明确结束并继续下一句。搜索支持显式选择 SearXNG，未配置地址时不改变原有提供方。最终真实模型主链 **15/15**、记忆与主动集成 **8/8**、工程回归 **225** 项通过，网页与发行包检查通过；服务仍停止。细节见[后续实测](../operations/evaluations/2026-10-31-personal-workflows.md#11-月-1-日长期运行的压缩学习与退出)，完整 Turn 超出学习窗口仍待解决。

个性表达支持温暖、直率、幽默、追问、展开程度和表情的独立组合，以及补充偏好。未固定维度沿用人物底稿与已确认偏好；明确的本轮任务格式优先。配置经同一宿主持久保存，不改写用户的 `VEDA.md`，也不另建人格数据库。对话与已获准的主动交流共用表达设定，具体用法和验证边界见[个性与相处方式](../handbook/personality.md)。

回应方式也可独立组合：遇到困扰时先听或回应后给办法，普通闲聊问到再建议或合适时顺带提一个想法。本轮明确要求优先，表达方式不授予额外工具、后台或发送权限。14 个开源项目的定位与人格设计输入、实现分工和言行检验见[人格设计](../architecture/personality.md)。

消息事实保留在 Ledger，图记忆和向量缓存可由完整来源恢复。
记忆具备语义召回、情景联想、原文引用、范围隔离和显式反馈；
具体能力是否有效，要看[当前验证](../operations/verification.md)中的实验条件与结果。
程序查询、Agent 工具和按出处展开原文已经接通；公开历史实验保留了强基线与失败。
召回的预算只花在请求看不到的内容上：原文仍在当前对话里的候选不再重复注入正文，而是花一行索引并保留可读回出处的 `ref`；两个判断在首次查询时写进回执，重渲染与重启字节一致。固定 12 轮历史、15 轮提问下每轮实时召回由 2393 字降到 757 字；窗口规则的回答质量由 `eval.memory_depth --suite window-v1` 单独对照，不与开销合并评估——该对照已给出结果：确定性上初始材料 2390 → 820 字而参考值可达两臂同为 12/12，回答质量在该夹具上为 9/12 对 6/12，但配对检验 p = 0.45，本轮分不出两臂差别；两臂均未编造编号。公开基准另扩到 [LongMemEval-S 140 题](../operations/evaluations/2026-11-06-memory-parity.md)：120 道可回答题上不给历史 0/120、加记忆约 56%（配对 68 比 2，p < 10⁻¹⁵），而本项目配置与朴素向量检索等价（差值 95% CI [−7.6, +5.9] 个百分点），因此不以回答准确率作为卖点。该组还拿掉了规则前提——生产里正文被 withhold 的唯一条件是它仍逐字留在本次请求里，这条由突变验证过的回归守着。得出这格之前先修了三处取证缺陷并钉成回归，见[窗口规则](../operations/evaluations/2026-11-06-memory-window.md)。对话里的召回卡片标出每条经历是正文、索引行、已在上文还是仅候选，预算流向因此可见。

引擎已采用上游到 `5ddd5ebb` 的实现：固定 150 轮各三次，学习中位数 47.66 s → 20.34 s，检索均值 47.96 ms → 11.62 ms（编译内核随 `memory` extra 默认生效，峰值由 52 MiB 升到约 77 MiB）。v3 之前发布的检查点在读取时被拒绝并要求显式重建，不会被静默重写成 v3。程序来源准入可以指定记忆范围——`persist_memory` 只控制写入，读取由范围的召回策略决定，没有范围的会话原先会照常被注入召回。

主动交互侧：事件调查与空闲规划各自可以选用更便宜的模型；已送达反馈按有界权重影响同一来源后续条目进入兴趣池的质量，明确要求逐条调查的条目不受影响，权重与依据可在跟进详情查看，上线前可用 `eval.feedback_replay` 在真实记录上离线核对;交办的目标按自己的轮次推进，带 token 预算与空转熔断，目标运行期间空闲规划主动让位。

记忆重点打磨三种体验：从召回线索继续查到长记录的原始细节、让过去的个人条件参与今天的行动，以及重试和恢复后仍能复核原始出处。场景与证据见[记忆设计](../architecture/memory.md#值得打磨的使用场景)。融合和片段模式保持显式选择。

事件入口支持 Content、Alert、Context，Wake 可以调查、分享、跳过并核对投递回执。
工作台的[跟进](../handbook/followups.md)已把原始对话、发布源、静态网页及只读 IMAP、调查、证据、投递和反馈接成用户操作路径。
普通聊天也已接入创建、查看依据、修改规则、暂停和恢复；操作绑定实际会话与本轮原始输入。
启动前检查主动联系和通知位置，调用重试沿原生工具身份读取持久回执；后台任务不能自行新增关注。
[聊天交办实测](../operations/evaluations/2026-10-23-personal-assistant.md)在展览与陶艺两场景各通过 12/12 项验收，覆盖历史更正、新规则跳过、依据查询和恢复；慢请求与超窗口学习失败仍在报告中保留。
可修改后续关注规则，修改本身和规则版本一同记入原始消息账本；结果评价不会自动变成永久偏好。
新规则可用于手动复查已接纳内容，保留旧决定和原来源；同内容、同规则的复查重试复用回执。
每次调查直接核对对应规则的原始用户记录，历史经历仍由范围内记忆读取，二者不互相替代。
明确要求逐条调查的订阅独立于兴趣阈值；调查继承发起对话的记忆范围，通知位置可以单独配置。
Drift 已接入可选的空闲思考：按选定对话与记忆生成有出处的聊天接续、事项协助或研究提案，经原生 Wake 核对后分享或跳过。主动接续聊天有独立开关，不要求伪装成研究成果；空闲等待、规划预算、同讨论去重、暂停与交接恢复共用原有链路。当前围绕每次新讨论进行一次有界规划，长期主动交流价值仍需继续验证。入口见[空闲思考](../handbook/memory-proactive.md#空闲思考)。
IMAP 协议与本地 TLS 邮箱已有接入；具体服务商账户、登录网页、日历与连续多日提醒质量仍需验收。具体场景与设计依据见[个人工作流](../architecture/design-direction.md)。
