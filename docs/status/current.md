# 当前状态

Kirakira 的产品方向是有长期记忆、会主动交流并持续帮主人做事的个人 AI 伙伴，面向日常交流、学习、生活与工作。持续跟进、原文核对和可纠正的判断是已经打磨的具体工作流；整体体验和未完成部分见[产品定位与设计](../architecture/design-direction.md)。

Kirakira 使用同一个 Runtime 管理对话、记忆、工具、项目和后台执行。
模型由可替换的 driver 提供；Python、SDK 与评测使用同一个 `.venv`。
工作台已接入记忆召回预算、长期档案、对话与子任务、定时任务、后台通知、命令和 Web 工具的原生设置；参数保存经插件配置换代生效，留空可恢复默认。入口见[运行参数](../handbook/start.md#运行参数)。

消息事实保留在 Ledger，图记忆和向量缓存可由完整来源恢复。
记忆具备语义召回、情景联想、原文引用、范围隔离和显式反馈；
具体能力是否有效，要看[当前验证](../operations/verification.md)中的实验条件与结果。
程序查询、Agent 工具和按出处展开原文已经接通；公开历史实验保留了强基线与失败。
图记忆尚未证明普遍优于向量，融合和片段模式保持显式选择。

事件入口支持 Content、Alert、Context，Wake 可以调查、分享、跳过并核对投递回执。
工作台的[跟进](../handbook/followups.md)已把原始对话、发布源、静态网页及只读 IMAP、调查、证据、投递和反馈接成用户操作路径。
可修改后续关注规则，修改本身和规则版本一同记入原始消息账本；结果评价不会自动变成永久偏好。
新规则可用于手动复查已接纳内容，保留旧决定和原来源；同内容、同规则的复查重试复用回执。
每次调查直接核对对应规则的原始用户记录，历史经历仍由范围内记忆读取，二者不互相替代。
明确要求逐条调查的订阅独立于兴趣阈值；调查继承发起对话的记忆范围，通知位置可以单独配置。
Drift 目前负责提案状态和结算，持续生成空闲提案的生产者仍需补齐。
IMAP 协议与本地 TLS 邮箱已有接入；具体服务商账户、登录网页、日历与连续多日提醒质量仍需验收。具体场景与设计依据见[个人工作流](../architecture/design-direction.md)。

[邮件与可纠正跟进实验](../operations/evaluations/2026-10-21-mail-followups.md)保留了 12 个带历史条件场景中 11 个判断正确、12 个召回到相应条件的首轮结果，以及一个误判经用户澄清后复查的独立干预。它支持具体工作流，不构成公开通知准确率或其他模型的质量保证。
