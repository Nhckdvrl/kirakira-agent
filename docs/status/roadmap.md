# 交付与研究路线

## 当前重点

- 产品定位：陪伴型、助理型、主动交互型的个人 Agent；覆盖日常交流、兴趣、学习、生活与工作。持续跟进和原文取证是具体工作流。
- 个性已支持六个表达维度、支持与建议两个行为偏好，以及补充文字与可选说话示例；继续检验多轮稳定性、隐含追问及缺少素材时的事实克制。实际功能正确、行为符合、风格可辨识和用户喜欢是不同指标；不保留缺乏可观察区别的中间选项。
- 记忆：优先打磨长记录的原文取证、个人历史参与后续行动，以及长期使用中的出处复核。
- 评测：按具体场景证明记忆的价值，记录最终答案或行动、读取开销与失败边界；整体榜单排名不是交付目标。
- 持续工作：任务与工具效果可追溯，重启后接续已有执行状态。
- 双主动：事件调查与有历史依据的空闲规划均沿既有执行链路运行；继续验证日常价值、预算、停止控制与长期时机。

对话、模型、工具、消息账本、图记忆、Markdown 档案、项目、后台任务和投递由插件组成。
默认组合与可选提供方见[插件清单](plugin-inventory.md)，架构见[总览](../architecture/overview.md)。

## 仍需验证或补齐

- 长记录取证已完成固定初始材料的配对实验，困难题有依据正确回答 0/8 → 5/8；后续扩大未用于开发的题目，改善未命中位置与控制题失败，并单独计追加材料和调用。结果见[场景实测](../operations/evaluations/2026-10-22-memory-scenarios.md)。
- 历史参与行动：保持新事件不变，改变过去的个人条件，检查最后的分享/跳过与采用的原始记录；扩展现有预算、安排和使用许可场景。
- 出处与恢复：继续核对重试、组件重载和完整重启后读到的来源，以及未发布尾部补学的状态；功能通过率单独报告。
- Markdown 学习已接入持久检查点、模型失败暂停后恢复与停止排空；单个完整 Turn 超出声明窗口仍不能学习，下一步设计有界学习并保留完整来源，不能把暂停重试当成已解决超窗。此前失败见[聊天交办实验](../operations/evaluations/2026-10-23-personal-assistant.md)。
- 固定预算公开实验已完成 42 题、9 个方案，用作广泛质量与退化检查。新增独立题目和 reader 服务于上述场景验证，不以所有分项胜出作为要求。
- 多次更正、跨会话线索和无法回答的问题已有分项结果，偏好与多会话推理仍需改善。
- 空闲规划已区分聊天接续、事项协助与研究，聊天有独立开关；四类日常话题已通过实际等待、去重与停止的受控验收，后续验证多日冷却、自然程度与长期价值。当前每次新讨论最多规划一次。
- 日常记忆与主动交流验收：兴趣、学习和生活安排的跨会话理解与更正；将普通聊天、信息触发和空闲主动分别计分，不能用邮件成绩替代全部伙伴体验。
- 外部数据源、设备与容器的实际账户和部署验收。
- 跟进已接入原始对话、公开发布源、静态网页区域差异、调查、证据、精确投递与反馈；继续开展连续多日使用验收，测量实际用户的有效提醒和误打扰。
- 只读邮件跟进已接入原生账户设置、增量 UID、同批线程合并、条件筛选与改期/取消调查；创建时可明确授权有限回查已有邮件。每次指定一个真实文件夹，尚无自动垃圾箱发现、跨文件夹去重、全邮箱搜索或 OAuth 自动续期；继续验收具体服务商和连续使用，再接等待回复与日历。
- 后台交办已补完成历史、状态与有出处的结果查询；隔离完整流程已通过自然交办、调查期间聊天、完成回访及重启查询。继续做连续使用与稳定延迟验收；回访停止或失败保留结果等待新输入，待回访的完成结果不占工作名额。
- 邮件截止时间先按原文核对，正常对话中确认后使用原生定时工具登记；自动提取并维护可更正的待办期限、自动替换旧提醒和含糊时间澄清仍需单独设计，不能把记忆里有日期当成已创建提醒。
- 明确规则修改、原始用户记录与手动复查已接通；聊天已支持创建、查看、修改、暂停和恢复。继续收集“召回正确但解释错误”的案例，扩大独立保留集，检查修正是否影响其他事项；跨对话管理和聊天内复查尚未接入。
- 普通更新的定时聚合、急事单独提醒和可复用场景模板，需结合用户标注验证。调研与逐场景验收见[设计依据](../architecture/design-direction.md)。
- 已送达反馈已接入有界关注权重：累计 4 条评价后按有用比例给出 0.5—1.5 的权重，参与兴趣池质量累加，明确要求逐条调查的条目不受影响，权重与依据可在跟进详情查看。离线回放 `eval/feedback_replay.py` 可在真实记录上核对会改变哪些联系决定并留出评价；尚未用留出集评分，也未验证真实使用中的有用提醒与误打扰比例，不能把决定翻转当成改善。
- 检索表示已采用上游 `cd0101f8`/`881f9fa7`（块预留、basin 增量常驻索引、惰性堆 Residual Push）：固定 150 轮各三次，学习中位数 47.66 s → 29.38 s，检索均值 47.96 ms → 30.53 ms，峰值分配不变。后续三条（schema v3 原地增量发布、numba 编译内核、单线程 BLAS 与分数记忆化）要改动本项目已修补的 `persistence.py`／`consumer.py` 并带 schema 迁移，需单独做迁移验收；兴趣原型峰值 1264 MiB → 286 MiB 那条也未采用。开销下降不等于检索质量提升，质量仍分开验收。
- 一键部署与更大的独立公开评测。

整体定位规定要提供什么体验；具体特色与能力边界由代码和实验支撑。尚未验证的方向不能写成已有优势。
功能与量化记录统一见[验证入口](../operations/verification.md)。
