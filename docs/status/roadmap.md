# 交付与研究路线

## 当前重点

- 产品定位：有长期记忆、会主动交流并持续帮主人做事的个人 AI 伙伴；覆盖日常交流、学习、生活与工作。持续跟进是一条特色工作流。
- 记忆：优先打磨长记录的原文取证、个人历史参与后续行动，以及长期使用中的出处复核。
- 评测：按具体场景证明记忆的价值，记录最终答案或行动、读取开销与失败边界；整体榜单排名不是交付目标。
- 持续工作：任务与工具效果可追溯，重启后接续已有执行状态。
- 双主动：事件调查与有历史依据的空闲规划均沿既有执行链路运行；继续验证日常价值、预算、停止控制与长期时机。

## 已有运行基础

对话、模型、工具、消息账本、图记忆、Markdown 档案、项目、后台任务和投递由插件组成。
默认组合与可选提供方见[插件清单](plugin-inventory.md)，架构见[总览](../architecture/overview.md)。

## 仍需验证或补齐

- 长记录取证：固定相同的初始材料，分别测“只看片段”与“允许继续读原文”；以带原文支持的最终答案为结果，另报追加材料、调用和读错位置的失败。
- 历史参与行动：保持新事件不变，改变过去的个人条件，检查最后的分享/跳过与采用的原始记录；扩展现有预算、安排和使用许可场景。
- 出处与恢复：继续核对重试、组件重载和完整重启后读到的来源，以及未发布尾部补学的状态；功能通过率单独报告。
- 固定预算公开实验已完成 42 题、9 个方案，用作广泛质量与退化检查。新增独立题目和 reader 服务于上述场景验证，不以所有分项胜出作为要求。
- 多次更正、跨会话线索和无法回答的问题已有分项结果，偏好与多会话推理仍需改善。
- 空闲规划生产、原文依据、预算、暂停和交接已接通；继续补充多日目标、按主题的长期冷却和新的探索价值。当前每次新讨论最多规划一次，不能据此宣称会持续自主发现一切值得做的事情。
- 日常记忆与主动交流验收：兴趣、学习和生活安排的跨会话理解与更正；将普通聊天、信息触发和空闲主动分别计分，不能用邮件成绩替代全部伙伴体验。
- 外部数据源、设备与容器的实际账户和部署验收。
- 跟进已接入原始对话、公开发布源、静态网页区域差异、调查、证据、精确投递与反馈；继续开展连续多日使用验收，测量实际用户的有效提醒和误打扰。
- 只读邮件跟进已接入原生账户设置、增量 UID、同批线程合并、条件筛选与改期/取消调查；下一步是具体服务商账户、令牌续期和连续使用验收，再接等待回复与日历。
- 明确规则修改、原始用户记录与手动复查已接通；继续收集“召回正确但解释错误”的案例，扩大独立保留集，检查修正是否影响其他事项。
- 普通更新的定时聚合、急事单独提醒和可复用场景模板，需结合用户标注验证。调研与逐场景验收见[设计依据](../architecture/design-direction.md)。
- 已送达反馈目前用于记录与检查，尚未自动影响后续筛选；先定义离线回放和保留集，再选择更新策略。
- 一键部署与更大的独立公开评测。

整体定位规定要提供什么体验；具体特色与能力边界由代码和实验支撑。尚未验证的方向不能写成已有优势。
功能与量化记录统一见[验证入口](../operations/verification.md)。
