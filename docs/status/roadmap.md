# 交付与研究路线

## 当前重点

- 产品定位：让过去的经历持续参与今天的判断和行动；以可运行的长期工作流程验收，而非功能数量。
- 记忆：真实历史中的关联召回、知识更新、时间条件、证据完整性和只读查询。
- 评测：冻结输入、等预算对照、回答与检索分开计分，保留失败和运行条件。
- 持续工作：任务与工具效果可追溯，重启后接续已有执行状态。
- 主动交互：事件进入后调查、分享或跳过；先测通知效果，再决定进一步产品设计。

## 已有运行基础

对话、模型、工具、消息账本、图记忆、Markdown 档案、项目、后台任务和投递由插件组成。
默认组合与可选提供方见[插件清单](plugin-inventory.md)，架构见[总览](../architecture/overview.md)。

## 仍需验证或补齐

- 固定预算公开实验已完成 42 题、9 个方案；扩大独立题量与 reader，避免根据小样本切换默认模式。
- 证明记忆在具体场景中的价值：历史更正、原文核对、跨会话线索与恢复。继续保留向量强基线，区分候选覆盖、片段包含与实际回答收益。
- 已打通片段到原文的按需读取；补充这一策略的总材料/调用预算对照，而非只增加上下文。
- 多次更正、跨会话线索和无法回答的问题已有分项结果，偏好与多会话推理仍需改善。
- 空闲任务提案的真实生产者、停止条件与注意力预算。
- 外部数据源、设备与容器的实际账户和部署验收。
- 跟进已接入原始对话、公开发布源、静态网页区域差异、调查、证据、精确投递与反馈；继续开展连续多日使用验收，测量实际用户的有效提醒和误打扰。
- 只读邮件跟进已接入原生账户设置、增量 UID、同批线程合并、条件筛选与改期/取消调查；下一步是具体服务商账户、令牌续期和连续使用验收，再接等待回复与日历。
- 明确规则修改、原始用户记录与手动复查已接通；继续收集“召回正确但解释错误”的案例，扩大独立保留集，检查修正是否影响其他事项。
- 普通更新的定时聚合、急事单独提醒和可复用场景模板，需结合用户标注验证。调研与逐场景验收见[设计依据](../architecture/design-direction.md)。
- 已送达反馈目前用于记录与检查，尚未自动影响后续筛选；先定义离线回放和保留集，再选择更新策略。
- 一键部署与更大的独立公开评测。

产品定位来自这些实验，尚未验证的方向不能写成已有优势。
功能与量化记录统一见[验证入口](../operations/verification.md)。
