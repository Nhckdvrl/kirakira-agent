# 所有权与局部更新

运行中只有一个原生 CompositionRoot。每个 provider 的 Fiber 持有自己的固定依赖、Effect、任务和
子 Fiber。依赖撤销后，消费者先退出；无关 provider 保持原实例。

## 实际执行入口

原生 `ctx.entrypoint`、`ctx.call_scope` 和 `FiberHandle.acquire_call` 接纳一次确切激活的调用。
owner 开始卸载后拒绝新调用，等待已接纳的调用实际结束再释放资源。
旧 Context 或旧工具菜单不能自动转向新实现。

工具注册到当前目录，ReAct 每次模型生成取具体菜单；同次生成返回的提议使用该菜单里的对象。
跨生成可以看到更新。主动 tick、整轮对话和子任务不持有全局快照。

## 文件和连接变化

插件安装先验证文件，再排空要替换的实例，更新已安装文件并接入当前代码。
当前选择运行失败时保持失败诊断，不把旧实现自动恢复成运行事实。

MCP 每个 server 使用独立 Fiber。未改变的声明不重新连接；改变的连接先撤销、排空再连接。
解析非法的声明在应用前报错；连接失败的有效选择保留在文件和状态中。
旧内容仅作为显式备份，修复文件或再次操作后重新应用。

## 退出与失败

原生 Fiber 先关闭接纳，通知依赖消费者退出，取消并等待自己创建的任务，等待实际调用完成，
关闭子树，然后派发 STOPPING 并逆序释放 Effect。

取消调用方不等于资源已经退出。物理关闭仍要完成；失败的资源与其依赖保留在原 owner 下供显式重试。
同一依赖链中，后取得的资源没有关闭成功时，不提前释放它仍需要的较早资源。
不相关的子分支仍会尝试关闭。

插件的类式 API、同步工具线程及 MCP 进程通过窄适配接入这些边界，不另建全局代际或恢复权威。
诊断使用原生 topology、readiness、health 和 incidents；已删除旧 snapshot、generation registry
与 reload journal 的并行协议。
