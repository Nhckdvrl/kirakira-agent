# Kirakira 开发与验证工作流

## 固定工作基线

使用单一 Python 环境、依赖锁与明确的源码版本。先定位具体组件的 `plugin.py`、
`contract.py`、实现文件和已有场景，再写代码。实现的来源、许可证、补丁与生成资产必须可追溯。

工作开始时确认当前分支、未提交改动和任务涉及的数据目录。生产 workspace、模型凭据与
开发临时工作区分开；临时验证在独立目录中运行。

## 写清楚行为合同

描述触发条件、输入身份、事实 owner、允许的效果、持久终态和失败后的恢复行为。
把“能运行”落实为可观察结果，例如：新 Input 提交之后，旧 Task 无权提交新 Output；
已开始的工具完成结算；重启读取相同 CallRef 的结果，不重新启动已完成的效果。

先确定类型和权限边界，再确定调用方向。跨插件共享 `contract.py` 的公共类型。
私有 command/dataclass 不跨 generation 传递；通过该 owner 的公开 RPC 或窄能力进入。

## 沿真实所有权实现

宿主只提供 Root、任务、执行授权、配置/凭据与插件管理能力。
业务数据库、后台任务、监听器和外部资源由普通插件拥有。

- Context 声明真实依赖，Fiber 固定 activation。
- Effect 先登记撤销责任，再取得或启动资源。
- Task 负责接纳、撤权与物理排空，不以裸 asyncio Task 代替业务授权。
- Ledger 保存原始消息和有序控制事实；派生状态保存指针与消费位置。
- Writer 固定来源、作者、正文种类与 exact CallRef，关闭即撤销新写权。
- OwnerState 将领域状态和消息提交置于同一事务。
- Bindings 保存实际来源及业务选择，恢复不靠同名工具或全局当前对象猜测。
- 工具先 prepare 固定目标，再授权、提交 intent、执行和记录结果。
- 托管进程、MCP、Workload 分别保留自己的借用与关闭生命周期。

业务代码保持单一权威入口。删除退出主链的旧实现，避免保留两套任务管理、消息提交或恢复规则。

## 用场景推动开发

先使用已有合同和已有测试夹具。为真正的新边界补一个能失败的场景，避免为每个内部函数复制测试。
按顺序推进：正常链路、取消与替换、提交失败、资源关闭、进程退出与重启。

使用 Event、真实事务、真实子进程与明确的阶段屏障制造竞争。
检查实际数据库、消息引用、效果次数、资源状态和最终回执；避免只检查 mock 被调用。

确定性模型对端负责控制时间和失败位置。真实模型负责验证工具协议、上下文、内容和多步行为。
两类结果分别记录，不把确定性对端计入真实模型评测。

## 验证完整执行链

使用正式 PluginManager 和同一套生产插件组合启动隔离 workspace。
测试从正式来源入口接纳输入，经过消息、任务、回复、模型、工具、执行设施与投递。
仅在测试真正需要的资源边界提供夹具；模型输出、工具授权和持久事实不绕过正式实现。

真实 API 测试要固定模型、专用端点、账户边界和配置。
连接和模型验证调用与业务调用账本分别说明计数范围。

每个场景保留输入、结果、消息或数据库证明与运行版本。
失败要区分实现问题、环境问题和评测断言问题。修复后保存新的结果，旧结果保持可追溯。

## 完成一轮修改

先运行与变更直接相关的检查，再运行完整必要回归。
前端执行类型检查和生产构建，Python 交付检查 wheel/sdist 的关键模块与入口。
更新架构、启动和迁移文档，使文档只描述当前真正运行的实现。
运行命令统一使用 `uv run --frozen --no-sync` 进入已经同步的 `.venv`；本地记忆依赖使用 `--extra memory` 安装，不另建评测环境。

提交前检查差异、来源摘要、秘密信息、生成文件和目录整洁度。
提交和推送后确认远端提交与 CI 结果。
完成的标准是行为合同和实际链路成立；测试数量、目录名称和源码摘要各自只证明其明确范围。

## 目录维护

| 目录 | 职责 |
| --- | --- |
| `kirakira_agent/`、`main.py` | 发行入口、工作区初始化与命令封装 |
| `agent/`、`bootstrap/`、`core/`、`infra/`、`utils/` | 宿主、插件生命周期、任务与公共基础设施 |
| `plugins/`、`bundles/` | 业务组件、提供方和发行组合 |
| `frontend/` | Web 源码、共享前端包与类型合同 |
| `sdk/` | 客户端 SDK |
| `migrations/`、`plugins/gateway/schema/` | 数据升级与格式约束；历史迁移仍参与既有数据升级 |
| `skills/` | 随发行版提供的技能 |
| `tests/`、`eval/`、`scripts/` | 工程回归、可复现实验和维护入口 |
| `docs/` | 使用、架构、状态与验证文档 |
| `third_party/`、`LICENSE` | 代码来源、局部修改与许可证记录 |

运行数据放在仓库外选定的工作区；凭据、模型权重、数据集、临时脚本、测试输出和完整启动日志也留在私有外部目录。
只将报告实际引用的原始证据发布到统一证据目录，保留失败与实验版本，不提交重复工作区或原始服务器日志。
当前行为更新使用说明和状态页，日期报告只解释其原始实验，不把旧测试数量改写成当前成绩。

使用 `uv run --frozen --no-sync python -m scripts.clean_workspace --dry-run` 预览，去掉 `--dry-run` 清除缓存与打包残留。
`.venv`、`node_modules`、正在使用的界面制品、技能和数据库迁移属于有效依赖或实现，不按目录大小直接删除。
